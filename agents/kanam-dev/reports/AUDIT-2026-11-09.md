## 2. Defecto real 1: siete skills sin `description` en el runtime

Siete skills de `agents/kanam-dev/skills/` tienen `description: TODO: add
description` en el frontmatter:

```
api-integration-test, chaos-engineering, code-metrics, compatibility-testing,
dependency-advisor, performance-benchmark, threat-modeling
```

Verificado contra el runtime, no contra el archivo:

```
openclaw skills list --agent kanam-dev --json
  total listadas: 120
  con TODO: 7
```

**Impacto:** el modelo elige skills por `name` + `description`. Una skill con
`description: TODO` es, a efectos de seleccion, una skill sin descripcion. Las
siete existen y no se pueden enrutar. `threat-modeling` ademas tiene un `title`
duplicado que el validador metio y nadie limpio.

**Origen, trazado con git:** viene de `b5d2aed687` (2026-10-07), un commit que
puso el bloque que el validador generaba para desbloquear CI, con el `TODO` como
placeholder declarado. **No lo introdujo la ventana auditada.** La ventana lo
mantiene y agrega `name` + `metadata`, pero deja el `TODO`.

**Por que ningun gate lo atrapo:** `scripts/test-skills.sh` valida que el
frontmatter parsee y que los links existan. No valida que la `description` sea
util. Un `TODO` parsea perfecto.

## 3. Defecto real 2: dos copias divergentes de `check_em_dash.py`

Existen dos archivos con el mismo proposito y distinto contenido:

```
agents/kanam-dev/scripts/check_em_dash.py
scripts/check_em_dash.py
```

Ambas ya son informativas (exit 0), que es el contrato correcto tras la decision
del 2026-11-09. Pero divergen en docstring, en el mensaje de salida y en un
detalle: la copia del workspace documenta correctamente "Exit 0 = siempre"; la de
`kanam-dev` conserva en su docstring "Exit 1 = encontro guiones largos", que ya no
es cierto.

**Impacto:** bajo hoy (ambas devuelven 0), real mañana: dos fuentes de verdad para
una regla que se acaba de retirar. El commit `c64c497aa6` del 2026-11-09 actualizo
las dos, y aun asi quedaron distintas.

**Nota de alcance:** `AGENTS.md` de `kanam-dev` declara `scripts/` como parte de la
superficie del rol, asi que la copia no es basura: es una duplicacion declarada.
