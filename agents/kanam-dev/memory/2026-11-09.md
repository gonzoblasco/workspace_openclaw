### Defecto real 1: siete skills con description TODO

Siete skills tienen `description: TODO: add description` en el frontmatter:
`api-integration-test`, `chaos-engineering`, `code-metrics`,
`compatibility-testing`, `dependency-advisor`, `performance-benchmark`,
`threat-modeling`.

Verificado contra el runtime, no contra el archivo:
`openclaw skills list --agent kanam-dev --json` lista 120 skills, 7 con TODO.

Impacto: el modelo elige skills por name + description. Una description TODO es
una skill que no se puede enrutar. Existe y no se selecciona.

Origen trazado con git: `b5d2aed687` (2026-10-07), que puso el bloque que el
validador generaba para desbloquear CI, con TODO como placeholder declarado. NO
lo introdujo la ventana auditada.

Por que ningun gate lo atrapo: `test-skills.sh` valida que el frontmatter parsee y
que los links existan. Un TODO parsea perfecto. Mide presencia, no utilidad.

### Defecto real 2: dos copias divergentes de check_em_dash.py

`agents/kanam-dev/scripts/check_em_dash.py` y `scripts/check_em_dash.py` existen
con el mismo proposito y distinto contenido. Ambas ya son informativas (exit 0,
correcto tras la decision del 2026-11-09), pero divergen. La copia de kanam-dev
sigue documentando "Exit 1 = encontro guiones largos", que ya no es cierto.

Nota de alcance: `AGENTS.md` de kanam-dev declara `scripts/` como parte de la
superficie del rol, asi que la copia no es basura: es duplicacion declarada.

### Hallazgo menor

`keep-merge-deprecate.md` afirma que 7 skills tienen "name missing". Ya tienen
name; el faltante real es la description. El sintoma se movio y el diagnostico no.
