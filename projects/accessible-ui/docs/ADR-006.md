# ADR-006: Semantic Release & Changelog Strategy

## Decision

Use `semantic-release` for automated versioning with npm convention-based tags.

## Contexto

The regeneration creates a clean foundation. Need consistent versioning strategy:

- **v1.0.0-next.1** → current regen version
- **Semantic versioning**: MAJOR.MINOR.PATCH format
- **Changelog entries**: Auto-generated from commit messages

## Decision

### Versioning Rules

| Range | Trigger | Target Version |
|-------|---------|----------------|
| BREAKING CHANGE (feat: combine + change API) | Pull request merge to main | MAJOR + 1.0 |
| New features (feat: * ) | PR to develop branch | MINOR + x.y.z |
| Bug fixes (fix: *) | PR with fix prefix | PATCH + x.y.z |
| Docs only (docs:*) | PR with docs prefix | NO CHANGE |

### Changelog Format

```markdown
## v1.0.0-next.2 (TBD)

### Features
- Add focus trap to Modal component (#XXX)

### Bug Fixes
- Fix ArrowUp wrap behavior in Combobox
```

### Release Strategy

```bash
# Auto-version on PR merge
npx semantic-release

# Manual version bump (dev)
npm version patch
```
