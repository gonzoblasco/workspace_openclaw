# kanam-lab - Brief

- **Proposito:** playground local de IA (Gradio) para explorar modelos, STT y RAG sin salir de la maquina. Experimentar con Python como protagonista en la capa de IA, fuera de React/JS.
- **Fase 1 (2026-09-12):** chat comparativo de 2 modelos de Ollama lado a lado, misma pregunta a ambos. Servidor en `0.0.0.0:7860`.
- **Fase 1.5 (2026-09-12):** un solo input envia el mismo prompt a ambos modelos en paralelo (streaming).
- **Fase 2 (2026-09-14):** tab STT - transcripcion de audio 100% local. Paquete real: `mlx-audio==0.5.3` (el nombre `mlx-stt` no existe en PyPI), modelo `mlx-community/GLM-ASR-Nano-2512-8bit` (~2.3G, cache HF, carga lazy), conversion webm->wav con `afconvert`. Docs: `docs/STT.md`. Commits `e82d86d`, `6ace8a4`.
- **Fase 3 (2026-09-14):** tab RAG - busqueda semantica sobre la memoria del workspace (dailies + learnings). Embeddings locales `qwen3-embedding:0.6b` + coseno (mismo flujo que memory-search.py), sintesis con deepseek-v4-flash. E2E OK: "reindex 451/451, 2857 chunks, fix SHA256->Ollama" recuperado con fuentes reales. Commit `af2863e`.
- **Fase 4 (2026-09-14):** registro automatico de duelos - cada comparacion del chat se guarda en `kanam-lab.db` (local, gitignored): prompt, modelos, longitud de cada respuesta, veredicto por extension (heuristica de registro, no juicio de calidad). Tab "Duelos ⚔️" con historial (Dataframe, boton refrescar). E2E: duelo real registrado (#1, deepseek 200 vs glm 219 chars) y confirmado en DB. Commit `9aa4c6b`.
- **Fase 5 (2026-09-14):** juez automatico - un modelo tercero (deepseek-v4.1-flash por defecto, nunca uno de los duelistas) evalua cada duelo y devuelve A/B/empate con razon. DB migrada (judge_verdict, judge_reason, judge_model) con fallback a la heuristica de extension si el juez falla. Nuevo endpoint /load_stats: ranking por modelo (duelos, victorias, empates, % victorias). Fix de robustez: num_predict 600 + parser regex para JSON truncado. E2E OK (duelo #4 juzgado). Commit `b0ce80f`.
- **Fase 6 (2026-09-15):** (a) guardar texto de las respuestas (text_a/text_b) - antes solo el largo, asi que re-juzgar era imposible; (b) re-juzgar historicos: con texto guardado juzga la original, sin texto RE-JUEGA el prompt (mismos modelos) y marca el duelo como rejugado (transparencia); boton "Juzgar las pendientes" + endpoint /do_rejudge; (c) RAG sobre learnings_enriquecido COMPLETO: contenido entero (sin truncar), tags, categoria y fecha, busqueda hibrida (coseno + bonus por match de tags/titulo). Resultado: 6/6 duelos juzgados. Commits `afc21a3`, `8ade922`, `7e5687d`.
- **Terminologia (2026-09-15, version FINAL tras 3 iteraciones):** la iteracion de la guerra quedo así - el chat comparativo es **"⚔️ Batalla de Modelos"** (la batalla = el experimento puntual, dos modelos con el mismo prompt), y el historial es **"⚔️ Historia de Batallas"** (lo mas descriptivo, decidio Gonzo sobre 'Guerra de Modelos'). La unidad es una **BATALLA**, las stats son "Tabla de posiciones". En codigo/DB interno sigue diciendo "duelos" (renombrar la tabla no aporta y es riesgoso). El export va a memory/batallas.md.
- **Bugs encontrados (2026-09-15):** (1) el prompt se guardaba truncado a 500 chars y se mostraba a 60 ("distinto al que se corrio" - reportado por Gonzo); ahora completo. (2) `qwen3.5:cloud` devuelve contenido VACIO siempre (verificado len=0 con num_predict 200 y 800) y era el juez elegido cuando los 2 primeros candidatos eran los duelistas -> agregado JUDGE_BLOCKLIST + fallback en cadena de jueces.
- **Fases pendientes:** nada en el lab. Nota: la batalla ahora es CONVERSACION ESPEJO (ver README).
- **Conversacion espejo + juez del hilo (2026-09-15, concepto que pidio Gonzo):** la batalla deja de ser un disparo unico y pasa a ser dos conversaciones paralelas que reciben los MISMOS mensajes turno a turno (layout de mensajero: chats arriba, input abajo). El registro ya no es automatico al primer turno: se juzga cuando Gonzo aprieta 'Juzgar el hilo completo' (judge_thread), y el juez evalua TODA la conversacion de cada modelo (thread=True en _duel_judge: system prompt de evaluador de hilos, contexto 3000 chars por lado, guarda el transcript USER/ASSISTANT en text_a/text_b). UI: boton 'Enviar a ambos' + 'Juzgar el hilo completo' + 'Limpiar'. E2E: 2 turnos espejo + batalla #13 registrada con veredicto sobre el hilo. Nota de debugging: el gradio_client NO serializa tuplas del Chatbot (usa dicts) - el E2E por API fallo, pero la UI real (Playwright + funcion pura) funciona; los endpoints /thread_turn y /judge_thread estan vivos.
