# Workflow: Product Discovery

## What it does

Guides from initial idea to product definition ready to build.

## Phases

### 0. Ideation (optional)
If the idea is vague or needs exploration:
- Brainstorming techniques (SCAMPER, inversion, first principles)
- Map of existing solutions
- Problem definition in one sentence

### 1. Intake
Capture idea, context, problem to solve.

### 2. Evaluation
Market, competitors, technical viability (can we build it with our stack? Estimated time? Technical risks?), strategic fit.

### 3. Definition
MVP, personas, features, metrics, positioning.

### 4. Specification
Feature specification (delta if project exists, as-built if new), architecture decisions.

### 5. Go/No-Go
Decision to build or iterate.

### 6. Retrospective (post-launch)
What went well? What didn't? What did we learn? Update status.

## Detailed Mode (--detailed)
For complex projects, generates:
- BRIEF.md
- EVALUATION.md
- DEFINITION.md (expanded with PRD, user personas, features)
- ARCHITECTURE.md (early technical decisions)
- DESIGN.md (style guide and UI)
- DATA_MODEL.md (data schemas)
- ROADMAP.md
- STATUS.md
- TRACKER.md (progress tracking)

## Outputs
- BRIEF.md
- EVALUATION.md
- DEFINITION.md
- ROADMAP.md
- STATUS.md
- Architecture decisions
