# ADR-001: Product Pipeline Integration

**Status:** Accepted  
**Deciders:** Gonzo / Kanam  
**Fecha:** 2026-07-19  
**Origen:** kanam-workflow

## Decision

Integrate the 5 core product management skills into a sequential pipeline for end-to-end product lifecycle management.

## Context

Kanam has evolved from isolated skills to a cohesive pipeline capable of managing full product lifecycles from idea to sustainability. Gonzo operates with multiple concurrent projects (BrainWeb, SoporteML v2, KanamAI), requiring systematic coordination across:

- **profile-positioning**: Market viability and opportunity assessment
- **product-orchestrator**: MVP definition and strategic evaluation
- **sdd-brownfield**: Technical specification as-built documentation
- **ai-copilot-structure**: Formal structure with OpenSpec artifacts
- **adr-framework**: Technical decision tracking
- **product-reset**: Foundation to sustainability phase execution

Current skill usage shows overlap (e.g., multiple orchestrators, no single product reset trigger), creating potential for inefficient resource allocation and unclear ownership.

## Consequences

1. **Clearer ownership per stage**: Each skill has defined input/output boundaries
2. **Reduced duplication**: profile-positioning → product-orchestrator feed ensures evaluation quality before spec work
3. **Standardized pipeline**: 9-step workflow applies consistently across all Kanam products
4. **Faster iteration**: Go/No-Go gates at defined checkpoints prevent wasted effort on unviable projects

## Implementation Notes

```bash
# Pipeline invocation pattern:
kanam-pipeline --start evaluate --target <product-slug>

# Expected artifact chain:
1. profile-positioning/audit-report.md
2. product-orchestrator/mvp-definition.md
3. sdd-brownfield/BRIEF.md (OpenSpec)
4. ai-copilot-structure/structure-docs/
5. adr-framework/ADR series starting at ADR-001
6. product-reset/foundation-plan.md
```
