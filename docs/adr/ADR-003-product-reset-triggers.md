# ADR-003: Product Reset Triggers

**Status:** Accepted  
**Deciders:** Gonzo / Kanam  
**Fecha:** 2026-07-19  
**Origen:** kanam-workflow

## Decision

Define explicit, measurable triggers and criteria for transitioning between the 5 phases of `product-reset` (Foundation → Visibilidad → Adopción → Comunidad → Sostenibilidad), preventing premature phase advancement or stagnation.

## Context

Gonzo's experience with SoporteML and BrainWeb shows that:
- Foundation can be completed in 1-2 weeks for MVPs
- Without clear metrics, teams may skip to "Growth" too early
- Community engagement (especially OSS) can take months before yielding results
- Sustainability planning requires baseline data collection first

Ambiguity around when to advance phases leads to:
- Incomplete foundation work
- Insufficient user feedback before scaling
- Premature infrastructure investment

## Consequences

1. **Predictable timelines**: Known duration per phase (Foundation: 7-14 days, Visibilidad: 2-3 weeks, Adopción: 4-6 weeks)
2. **Objective gating**: Metrics-driven advancement (not opinion-based)
3. **Reduced context switching**: Clear handoff points between phases
4. **Better resource allocation**: Skills know when to engage and when to wait

## Trigger Definitions

| Phase | Primary Triggers | Exit Criteria |
|-------|-----------------|---------------|
| Foundation | Spec complete, scaffold started | MVP deployable with auth |
| Visibilidad | MVP live, 3+ feature PRs submitted | Core metrics baseline set |
| Adopción | 10+ meaningful interactions OR engagement loop closed | Retention rate > baseline |
| Comunidad | 2+ OSS contributions accepted OR 1 maintainer relationship | Community roadmap visible |
| Sostenibilidad | Stable ops (no P0), revenue model defined or viable | Scale plan approved, infrastructure measured |

## Implementation Notes

```bash
# Advance phase with criteria validation:
product-reset --advance FOUNDATION -> VISIBILIDAD \
    --validate "MVP_DEPLOYED=true" \
    --metrics {user_sessions:15,pr_count:2}

# Check readiness for next phase:
product-reset --check PHASE="VISIBILIDAD" \
    --required {deployed:true, baseline_metrics:true}

# Trigger from external event (e.g., OSS merge):
kanam-pipeline --on-event PR_MERGE --type ADR_SUCCESS \
    --target brainweb-v2 \
    --action reset --phase ADVANCE --trigger OSS_CONTRIBUTION
```
