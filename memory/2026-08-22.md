## Sesión: Diagnóstico y fix de OpenClaw (20:29-21:00) - infraestructura

Gonzo reportó que OpenClaw no mostraba los modelos de Ollama en el TUI al lanzarlo desde el CLI de Ollama, y que al inicio había warnings de version/config.

### Qué se hizo (debugging en cadena)

1. **Warnings de plugins canvas/device-pair**: config huérfana de plugins bundled deshabilitados. Removí las entradas de `plugins.entries` (backup `openclaw.json.bak.manual-before-plugin-clean`).
2. **Versión vieja de OpenClaw en nvm**: `~/.nvm/.../openclaw` = 2026.6.10, instalada global en node v24.9.0 de nvm. Cuando Ollama lanza OpenClaw (spawn desde shell de login zsh que carga nvm), resolvía a esa versión vieja. **La desinstalé** - ahora `openclaw` resuelve siempre a homebrew 2026.7.1-2.
3. **Node de nvm desactualizado**: default era v24.9.0, que NO soporta OpenClaw 2026.7.1-2 (requiere >=24.15.0). Instalé v24.18.0 en nvm y lo seté como default.
4. **Modelos de Ollama ocultos en el TUI (causa raíz final)**: `agents.defaults.models` en openclaw.json actuaba como **allowlist estricta** - solo `openrouter/auto`, `openrouter/free` + el default. El model picker del TUI (`visibleCatalog` policy) solo mostraba esos 3, ocultando los 9 modelos de Ollama. **Fix: agregué el wildcard `ollama/*`** a `agents.defaults.models`. Hot-reload aplicado, los 9 modelos volvieron.

### Causa raíz del misterio
No era un bug ni residuo de OMLX/LMStudio. Es comportamiento por diseño: en OpenClaw, `agents.defaults.models` definido sin wildcard de provider = allowlist estricta del picker. Para permitir todos los modelos de un provider, usar wildcard `provider/*`.

### Config final relevante
```json
"agents": { "defaults": { "models": {
  "ollama/*": { "alias": "Ollama" },
  "openrouter/auto": { "alias": "OpenRouter" },
  "openrouter/free": {}
}}} }
```
