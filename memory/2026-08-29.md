# Daily 2026-08-29

## Sesión 2: Comparativa de modelos LLM para el pipeline A/B (noche)

Gonzo propuso probar modelos con un prompt pesado de arquitectura: diseño de agente autónomo de mantenimiento para monorepo TS publicado a npm, 7 secciones (ejecución, contexto, verificación, seguridad, recuperación, métricas, trade-off final). El mismo prompt fue a 5 modelos.

### Resultados

1. **Kimi K2.7 Code (xhigh)** - el mejor pensador. Insight que cambia el diseño: tiers de autonomía que se GANAN con métricas (auto-merge se conquista con escape rate bajo durante N issues, no se declara). También: caché de sesión invalidada por hash de commit, manejo fino de falsos positivos (tests flaky con 2 pasadas), separación de contexto por etapa.
2. **GLM 5.3 (sin razonamiento visible)** - el mejor criterio central: "el que planifica debe ser el que edita; el plan escrito se invalida al contacto con la realidad". Citó la experiencia real del pipeline A/B (el revisor puede introducir bugs al "corregir" código correcto). Principio rector: límites verificables fuera del modelo, nunca promesas del prompt.
3. **Kimi K3 (xhigh)** - el mejor presentador (gráficos, snippets, ejemplo concreto del Button), pero inventó números (~200ms por handoff, ~15% overhead) para sonar preciso, y esquivó la pregunta del prompt sobre merge sin revisión humana. Pulido > sustancia en este caso.
4. **GLM 5.3 Flash (sin razonamiento visible)** - sorprendentemente bueno para ser el "chico": serialidad de la escritura, orden de evidencia (stack trace > grep > import graph > exploración), disciplina red→green, límites verificables fuera del modelo.
5. **DeepSeek V4 Flash (xhigh)** - el más estructurado y didáctico (tablas de trade-offs), el menos agudo operativamente. En max filosofa sobre su propia existencia (ya lo teníamos en ADR-040).

Todos se truncaron por límite de salida antes de la sección 7 (trade-off final) - es límite de salida del modelo, no del prompt.

### Decisiones

- **Motor del pipeline A/B: DeepSeek V4 Flash → GLM 5.3 Flash** (SIEMPRE en high). Más agudo, multimodal nativo, más barato. Documentado en TOOLS.md, MEMORY.md, CHANGELOG.md.
- **Pendiente:** probar Kimi K2.7 Code en high (el modo real del pipeline) cuando vuelva la GPU (Gonzo quedó sin GPU ~2 días). Si en high mantiene el nivel, sería el candidato más fuerte para el rol de motor.
- **Nivel de razonamiento:** el max NO fue driver de calidad - la familia del modelo sí. Los mejores outputs vinieron sin razonamiento visible. Regla nueva: agentes de código siempre en high; max solo para diseño difícil puntual. Kanam sigue en max (experimento futuro: una semana en high y comparar).

### Ficha GLM-5.3-Flash (verificada en docs.z.ai + Hugging Face)

- Multimodal nativo: imagen, video Y archivos (PDFs) como input.
- 1M de contexto, 131k output, 320B params totales / 18B activos (MoE), MIT.
- Precio Z.ai: $0.075 input / $0.25 output por 1M tokens.
- `reasoning_effort` low/high/max en backend (default max), pero Ollama no expone el knob.
- Ex "ox-alpha": estuvo en stealth en OpenRouter/OpenCode absorbiendo miles de millones de tokens de agentes de código reales antes de lanzarse. Benchmarks: Terminal-Bench 2.1: 84.3, Toolathlon: 78.4.
