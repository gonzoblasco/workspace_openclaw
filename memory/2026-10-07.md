### Hallazgo Crítico sobre Kimi-K3
K3 (Kimi-K3) es el modelo de LLM más potente usado para **generar las 3 skills**, no como agente executor actual. Se analizó una skill generada con K3: `a11y-at-validation`.

**Evidencia de complejidad demostrada**:
- Referencias reales a casos específicos: issues #4109 y #4110 de radix-ui/primitives sobre timing races en VoiceOver que ningún test unitario pudo detectar
- Tablas comparativas estructuradas (lo verificable por tests vs solo manualmente verificable)
- Reglas derivadas documentadas con fechas contextuales
- Flujo paso a paso para validación manual en Storybook/Playground
- Detección de patrones intencionales vs bugs reales
- Protocolo específico para custom elements (ElementInternals) que explícitamente dice "no confiar" en axe-core
- Manejo de edge cases específicos: preselection, placeholder, grouping

### Veredicto Arquitectónico

**La teoría de Gonzalo es incorrecta.** Las skills generadas con Kimi-K3 tienen un nivel de sofisticación técnica, detalle y estructura que modelos más ligeros simplemente no podrían replicar.

#### ¿Por qué Gemma4 como CORE sería problemático?

1. **Enrutamiento ciego**: Podría elegir una skill "similar pero incorrecta" por no captar las sutilezas semánticas que GPT-oss y K3 sí tienen.

2. **Fragilidad ante ambigüedad**: DeepSeek/ GPT-oss no solo "saben qué skill usar", sino que entienden el *matiz* de lo que se pide. Gemma4 sería un switchboard, no un director de orquesta.

3. **Paradoja de la complejidad**: A más skills, mayor dificultad de elección. No menor. Con 10 skills es fácil; con 200+ y lógica de alta densidad, el CORE necesita capacidad de búsqueda semántica aguda.

4. **Verificación comprometida**: Si DEV escribe pero Gemma4 revisa, el sistema tiene un cuello de botella de calidad que no detectaría errores sutiles en la delegación.

### Conclusión Operativa
**Arquitectura actual recomendada**:
- CORE mantiene `deepseek-v4.1-flash:cloud` (o nivel comparable) para enrutar y gestionar sesiones complejas
- Agentes especializados usan sus modelos óptimos (`gpt-oss:120b-cloud` para DEV/Critic)
- Gemma4 queda como agente especializado (Studio), no como CORE

**Justificación**: El costo de mantener un modelo más potente en CORE es la garantía de que el ecosistema no se degrada en scripts aislados. La calidad de las skills generadas por Kimi-K3 exige que quien las gestione tenga capacidad cognitiva comparable.
