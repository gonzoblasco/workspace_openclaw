## Cata empirica de 8 modelos (ADR-040)

### Contexto
Gonzo queria saber que modelo usar para cada situacion. Se hizo una cata a ciegas: el mismo prompt de debugging (pool exhaustion en Edge Functions + Sharp) se paso a 8 modelos, sin revelar que modelo era cual. Kanam juzgo los outputs sin saber el modelo.

### Resultados
| Output | Modelo | Perfil |
|--------|--------|--------|
| A | deepseek-v4-flash | Arquitecto exhaustivo, solucion completa |
| B | gemma4 | Pragmatico, va al hueso |
| C | glm-5.2 | Balanceado, fix + frontend |
| D | kimi-k2.7-code | Especialista tecnico, conoce el runtime |
| E | minimax-m3 | Practico, va directo al bug clasico |
| F | qwen3.5 | SRE/DevOps, enfocado en tooling |
| G | deepseek-v4-pro | DBA + infraestructura |
| H | kimi-k3 | Cirujano de precision, 85% certeza |

### Conclusion
No hay correlacion entre costo/tamano del modelo y calidad de respuesta. Todos resolvieron bien el problema. La diferencia es personalidad, no capacidad. Kanam acerto solo 1/8 en identificar los modelos a ciegas.

### ADR-040 creado
- `docs/adr/ADR-040-modelos-seleccion-por-tarea.md`: define perfiles de personalidad, guia rapida de seleccion, y casos especiales (vision, PDFs, bundles de codigo).
- Reemplaza ADR-006 (Capacidad Computacional DeepSeek).
- Regla operativa: Kanam debe sugerir modelo segun la tarea antes de comenzar.

## Lecciones
- Una skill de estudio debe definir SIEMPRE su ruta de artifacts. `learning-tracker` era agnostica y eso genero la inconsistencia. La nueva study-tracker tiene la regla explicita: `studies/<slug>/`.
