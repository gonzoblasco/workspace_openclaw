## Sesión: PR facebook/astryx #4022 — Review de ernestt

**Contexto:** Llegó un review request changes de ernestt (contributor de Meta) al PR #4022 de astryx. El PR fixea contrast failures WCAG 2.1 AA en tokens de color core.

**Review:**
- **Reviewer:** ernestt (CONTRIBUTOR)
- **Estado:** CHANGES_REQUESTED
- **Comentario:** "Our understanding is that disabled text and buttons are exempt from the contrast requirements"
- **Commit evaluado:** a04f81e822160e1ca24245e9495c1343c5d9dca2

**Tokens afectados por el comentario:**
- `--color-text-disabled` — ernestt dice que disabled text está exento de contraste
- `--color-icon-disabled` — probablemente también aplica (non-text exempto si es decorative/disabled)
- `--color-border-emphasized` — este NO está exento, es un token de borde activo

**Análisis de la objeción:**

1. **`--color-text-disabled`** — WCAG 2.1 SC 1.4.3 (Contrast Minimum) tiene una nota: "Text that is part of an inactive user interface component, that is 'disabled'..." no tiene requerimiento de contraste. **ernestt tiene razón parcial.** Sin embargo, hay debate: algunos equipos igual aplican contraste mínimo para legibilidad. La nota de la SC dice "no contrast requirement" para disabled text.

2. **`--color-icon-disabled`** — SC 1.4.11 (Non-text Contrast) aplica a UI components y gráficos. Un icono disabled podría considerarse "inactive" y por lo tanto exempto. Pero si el icono es informativo (no puramente decorativo), aplica 3:1.

3. **`--color-border-emphasized`** — Este NO es disabled. Es un borde activo (emphasized). **ernestt no objetó este token explícitamente**, pero su comentario general podría interpretarse como que el PR completo es innecesario. Sin embargo, `--color-border-emphasized` a 1.37:1 es claramente un bug — barely perceptible.

**Estrategia de respuesta:**
- Reconocer que ernestt tiene razón sobre la exención de disabled text en WCAG
- Argumentar que la decisión de diseño de mantener disabled text legible es una buena práctica UX, no solo compliance
- Para `--color-border-emphasized`: señalar que NO es disabled, es un token activo, y 1.37:1 es un bug real
- Proponer: revertir `--color-text-disabled` y `--color-icon-disabled` si el equipo prefiere mantener los valores originales, pero mantener `--color-border-emphasized`
- Preguntar si prefieren un approach más conservador (solo fixear border-emphasized)

**Respuesta publicada:** Reconocí la exención de disabled text, separé los 3 tokens, propuse revertir text-disabled e icon-disabled y mantener solo border-emphasized. Quedó duplicada por error (dos comments idénticos) - no se puede borrar reviews ya publicadas.

## Sesión: Investigación de modelos — ADR 006 actualizado

**Contexto:** Conversación fuera de contexto sobre consumo GPU de modelos en Ollama Cloud. Evolucionó a una investigación completa con datos reales de benchmarks.

**Hallazgos clave:**
- DeepSeek V4 Flash: AA Intelligence Index **47** (no 40 como decía el ADR original)
- DeepSeek V4 Pro: AA Index **52** (no 44)
- Kimi K3 descartado como opción viable — demasiado caro, demasiado pesado para el perfil de trabajo
- Brecha real Flash vs Pro: coding 1-2 pts, agentic 11 pts (Terminal-Bench), factual 23.8 pts (SimpleQA)
- Flash 2.3x más rápido que Pro (81 vs 36 t/s)
- Hardware local (Mac Mini M4 24GB) irrelevante para inferencia — todo cloud

**Decisiones:**
- Kimi K3 descartado de la ecuación
- ADR 006 actualizado con datos reales de hoy
- Estrategia simplificada: Flash default, Pro solo cuando Flash falle 2-3 veces

**Archivos modificados:**
- `docs/adr/ADR-006.md` — actualizado con datos reales, Kimi K3 eliminado

**Self-Reflection:**
- CONTEXT: Investigación de modelos + actualización de ADR
- REFLECTION: La conversación empezó como "fuera de contexto" y evolucionó a una investigación técnica completa que mejoró un ADR existente. Buena señal de que el sistema funciona — una pregunta casual llevó a datos concretos que mejoraron la documentación.
- LESSON: Cuando surjan preguntas de capacidad/comparación de modelos, ir directo a fuentes con datos (Artificial Analysis, BenchLM, Ollama official) en vez de estimar. Los números reales siempre son mejores que las aproximaciones.
