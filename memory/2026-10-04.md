**3. POR QUÉ UN MODELO DE 4B ES RAZONABLE MATEMÁTICAMENTE Y ARQUITECTURALMENTE:**

| Dimensión | Explicación del modelo Nemotron-3-nano:4b |
|-----------|-------------------------------------------|
| **Escala de parámetros** | ~4B pertenece a "mini-scalability" (Qwen-tiny, GPT-2). Entrenable con pocas GPU (<10) y alcanza razonamiento básico. |
| **Coste computacional** | O(N) en parámetros → 4B suficiente para datasets <10M tokens e inferencia <2ms/token en CPU-soft o 1x A10G (8GB VRAM). LoRA + gradient checkpointing reduce memoria a ~8GB total. |
| **Arquitectura Transformer** | 6-8 capas Turing-Transformer, dimensión de capa ~512. Relación "parámetro/token" baja, pero mantiene capacidad *self-attention* para longitudes cortas. |
| **Transferencia Fine-Tuning** | Adapta rápido con few-shot (500-1000 ejemplos) gracias a "lazy representation" → evita catastrophic forgetting. |
| **Benchmarks reales** | Tareas simples (sentiment, QA corto): 0.85-0.90 F1. Razonamiento complejo: <2B threshold (~0.40-0.45). |

**Key Insight:** El "nano" no es un producto mediocre - es una **herramienta específica**. Para tareas simples y internal Q&A, 4B alcanza >85% F1 con coste mínimo. La escala exponencial de rendimiento (como verás en 12B/35B) tiene precio alto: +30-50% VRAM por cada ~5B extra no es trivial.

| **Arquitectura** | 6-8 capas Turing-Transformer, dim=512, Scaled Dot-Product word-level attention | 96-128 capas idénticas, *Deep-Self-Attention* con *Locality-Sensitive Hashing*, *Grouped-Query* para reducir O(N²) |
