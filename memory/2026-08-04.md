# 2026-08-04

## create-stack — publish @gonzoblasco/create-stack@0.8.1 ✅

**Contexto:** Gonzo intentó publicar `@gonzoblasco/create-stack@0.8.1` y falló con `404 Not Found - PUT https://registry.npmjs.org/@gonzoblasco%2fcreate-stack`.

**Diagnóstico:** El 404 no era del scope ni del paquete — era que **no estaba logueado en npm** (`npm whoami` → 401 Unauthorized). Sin sesión activa, npm no deja publicar bajo ningún scope.

**Resolución:**
1. `npm login` (autenticación por browser OTP) → `Logged in on https://registry.npmjs.org/`
2. `npm publish` → `+ @gonzoblasco/create-stack@0.8.1` ✅

**Decisión de Gonzo:** quiere **mantener el scope `@gonzoblasco/`** como firma. Descartó publicar sin scope (Opción A). Posible rename futuro de la identidad del asistente a "kanam" (pero "aún soy yo quien habla" — el scope queda con firma gonzoblasco por ahora).

**Pendiente menor (no bloqueante):**
- Warning de npm: `bin[@gonzoblasco/create-stack] was renamed to bin[create-stack]`. npm auto-corrige la key bin en cada publish. Se limpia con `npm pkg fix` (renombra la key a `create-stack`). Cosmético, no rompe nada — el comando sigue siendo `npx create-stack`. ✅ **Resuelto** — Gonzo corrió `npm pkg fix` manualmente.

## Lecciones

- **npm 404 en publish scoped ≠ problema de scope.** Primero verificar `npm whoami` — si da 401, el fix es `npm login`, no tocar el scope. El scope `@usuario/` se resuelve solo si coincide con el username logueado.
- **npm login ahora usa browser OTP flow** (no token en consola). El notice sobre "tokens that bypass 2FA are being restricted" es la deprecación de tokens que saltan 2FA — a futuro conviene usar tokens con `mfa=publish` o `automation` para CI.
