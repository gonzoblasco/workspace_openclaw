## Lecciones

- Biome + tests no detectan errores de runtime ES (imports duplicados, referencias rotas). El build es el verdadero gate.
- No encadenar build + commit en un solo comando si partes del flujo ya pueden haber commiteado. Verificar build *antes* del commit.
- El pre-commit hook es la última red de seguridad, no el primer paso.
- Si un edit rompe un template literal, una "fix" automática de Biome puede convertir interpolaciones en texto literal sin que rompa el build. Hay que revisar visualmente los strings con `$` tras cualquier edición problemática.

## Incidente PWA: 404 en asset JS antiguo

- Gonzo reportó pantalla en blanco con error 404 de `index-CqBeXR9S.js`.
- Causa: el service worker v2 cacheaba `index.html` de forma "cache-first" y no cacheaba los assets JS/CSS hasheados. Tras varios deploys, el HTML cacheado apuntaba a un asset antiguo que ya no existía en el servidor, generando 404.
- Solución aplicada:
  - Se pasó a estrategia **network-first** para `index.html` (y navegación) para que siempre se sirva el shell actualizado.
  - Se agregó un **runtime cache** para assets hasheados (JS/CSS) y otros recursos que se descargan dinámicamente.
  - Se incrementó a `kanam-solitaires-static-v3` / `kanam-solitaires-runtime-v3` para forzar la activación del nuevo SW.
- Build, tests y Biome OK. Commit + push a `gonzoblasco/kanam-solitaires:main`.
- Nota: clientes con el SW v2 afectado pueden necesitar cerrar todas las pestañas o hacer hard refresh una vez para que el nuevo SW tome control.

REFLECTION: la documentación consumió más tiempo del esperado porque no existía una base previa; crear STATUS, DEFINITION, CHANGELOG y docs/ desde cero es costoso.
LESSON: iniciar documentación paralela durante el desarrollo, no solo al final de un milestone.

CONTEXT: bugfix de template literals rotos en Spider renderer.
REFLECTION: un error previo (backtick perdido) provocó que Biome "arreglara" template literals con interpolación convirtiéndolos en strings literales con `$`, lo que no rompe el build pero sí la funcionalidad.
LESSON: después de cualquier edición que afecte template literals, greppear por `$` suelto en strings y revisar visualmente.
BIASES DETECTED: confirmación (asumí que Biome safe-fix era segura).

CONTEXT: doble click en Spider no funcionaba.
REFLECTION: implementé `dblclick` y asumí que cubría móvil. El doble tap en navegadores móviles no dispara `dblclick`; requiere handler de `touchend` manual. También es posible que en desktop el problema fuera otro, pero agregar ambos handlers y mejorar touch-action es la solución completa.
LESSON: probar interacciones táctiles explícitamente; `dblclick` no es suficiente para PWAs móviles.
BIASES DETECTED: asunción de equivalencia desktop/móvil.

CONTEXT: 404 en asset JS antiguo tras deploy.
REFLECTION: el SW cacheaba `index.html` cache-first sin incluir los assets hasheados. Cada nuevo deploy invalidaba el HTML cacheado porque apuntaba a assets borrados.
LESSON: para apps con hashed assets, nunca usar cache-first en `index.html`; usar network-first y cachear hashed assets dinámicamente. Incluir tests/validación del SW si es posible.
