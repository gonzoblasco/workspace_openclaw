## El bug real del índice de git: `GIT_INDEX_FILE` en commits con pathspec <!-- project: github.com/gonzoblasco/workspace_openclaw -->

Síntoma: `git commit` moría con `error: invalid object 100644 4ff6d9df... for 'scripts/broken.sh'` + `error: Error building trees`, siempre **después** de que todos los tests del pre-commit pasaban.

**Causa raíz medida:** con `git commit -- <paths>` git pasa al hook un índice **temporal** vía `GIT_INDEX_FILE` como path **absoluto** (`.git/next-index-<pid>.lock`). Un test bats (`tests/bash/test-skills-scope.bats`) hace `git -C "$WS" add scripts/broken.sh` con `$WS` = `mktemp -d`. Hereda esa variable, así que escribe la entrada **en el índice real del repo** mientras lee el blob del repo temporal → objeto inválido. Sin pathspec (`git commit` normal) `GIT_INDEX_FILE` es relativo (`.git/index`) y no explota: **por eso el bug estaba latente desde antes y lo destapó el pathspec**.

Reproducido en `/tmp`: índice real contaminado con `scripts/broken.sh` + `git write-tree` fallando exactamente igual.

**Fix:** `env -u GIT_INDEX_FILE` en las tres invocaciones de tests del hook (bats, pytest, tests/node), aplicado a `.git/hooks/pre-commit` **y** `scripts/pre-commit.template` (3 ocurrencias en cada uno). Verificado: hook exit 0, índice limpio.

**Diagnósticos descartados en el camino (no repetirlos):** corrupción del índice (lo reconstruí con `rm .git/index && git reset` → falló igual), `bats` aislado (deja índice limpio), path relativo vs absoluto con `git -C` (el relativo no contamina).

`vite.config.ts` usa `cloudflare({ viteEnvironment: { name: 'ssr' } })`. El runtime del servidor es el binario **workerd** (plugin de Cloudflare), no el Node de Vite.

```
ERROR  Error fetching Ollama models: Error: Network connection lost.
INFO   LLMManager  Got 0 dynamic models for Ollama
```

`"Network connection lost"` es error propio de workerd; Node habría dado `fetch failed`. En macOS, workerd alcanza `127.0.0.1` sin problema → por eso el modo nativo funciona.

**Descartes hechos uno por uno (no repetirlos):** no es DNS (resuelve bien: `192.168.65.254` IPv4 + `fdc4:f303:9324::254` IPv6); no es IPv6 (`ENETUNREACH` desde el container, pero **IPv4 cruda tampoco funcionaba**); no es CORS de Ollama (`Access-Control-Allow-Origin: http://localhost:5173` OK); no es el timeout de 5 s (3/3 OK con Node desde el mismo container, 10.036 bytes).

### La persistencia del server: `setsid` no existe en macOS

`nohup` + `&` + `disown` **no sobrevive** al cierre de la sesión de exec: el proceso queda en el mismo process group y muere con el shell. Lo que sí funciona: `os.setsid()` vía `python3` (macOS no trae el binario `setsid`; `brew install coreutils` tampoco estaba):

```bash
nohup python3 -c '
import os, sys
os.setsid()
os.execvp(sys.argv[1], sys.argv[1:])
' pnpm run dev --port "$PORT" > "$LOG" 2>&1 &
```

Con eso el server queda en su propia sesión y sobrevive (verificado: listener vivo 1h+ después, PID 56815).

**Coherente con la lección ya registrada 3 veces el mismo día** (`memory/2026-10-20.md`, sección de la cata): *"nohup/setsid NO sobrevive al cierre del exec; lo que sobrevive es `background: true` del gestor de procesos de OpenClaw"*. Acá se resuelve del lado del script, con `os.setsid`.

**Otro detalle de pnpm:** `pnpm run dev -- --port 5174` mete un `--` suelto que rompe el parseo de react-router (`React Router Vite plugin not found in Vite config`). La forma correcta es `pnpm run dev --port 5174` (los args se anexan al comando final).
