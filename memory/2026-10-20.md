## El bug real del índice de git: `GIT_INDEX_FILE` en commits con pathspec <!-- project: github.com/gonzoblasco/workspace_openclaw -->

Síntoma: `git commit` moría con `error: invalid object 100644 4ff6d9df... for 'scripts/broken.sh'` + `error: Error building trees`, siempre **después** de que todos los tests del pre-commit pasaban.

**Causa raíz medida:** con `git commit -- <paths>` git pasa al hook un índice **temporal** vía `GIT_INDEX_FILE` como path **absoluto** (`.git/next-index-<pid>.lock`). Un test bats (`tests/bash/test-skills-scope.bats`) hace `git -C "$WS" add scripts/broken.sh` con `$WS` = `mktemp -d`. Hereda esa variable, así que escribe la entrada **en el índice real del repo** mientras lee el blob del repo temporal → objeto inválido. Sin pathspec (`git commit` normal) `GIT_INDEX_FILE` es relativo (`.git/index`) y no explota: **por eso el bug estaba latente desde antes y lo destapó el pathspec**.

Reproducido en `/tmp`: índice real contaminado con `scripts/broken.sh` + `git write-tree` fallando exactamente igual.

**Fix:** `env -u GIT_INDEX_FILE` en las tres invocaciones de tests del hook (bats, pytest, tests/node), aplicado a `.git/hooks/pre-commit` **y** `scripts/pre-commit.template` (3 ocurrencias en cada uno). Verificado: hook exit 0, índice limpio.

**Diagnósticos descartados en el camino (no repetirlos):** corrupción del índice (lo reconstruí con `rm .git/index && git reset` → falló igual), `bats` aislado (deja índice limpio), path relativo vs absoluto con `git -C` (el relativo no contamina).
