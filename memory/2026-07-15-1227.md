## payloadcms/payload #17342 — PR abierto ✅

**Issue #17232** era el más complejo del pipeline: data loss silencioso en el admin de Payload CMS. Un editor sube dos archivos a un block de Lexical rich text, y al seleccionar el segundo, el primero se borra silenciosamente. Sin errores, sin warnings. "The CMS randomly deleted my file."

### El bug

Cuando abrís un drawer (para seleccionar un upload), el `BlockComponent` se recicla — React lo oculta y lo vuelve a mostrar. Pero el `Form` dentro se re-inicializa desde `initialState`, que es un snapshot capturado cuando se creó el block. Los valores que el usuario seteó después (como el primer upload) se pierden.

El fix anterior (#14295) intentó mergear los valores actuales, pero solo recorría las keys que ya existían en el cache — si un campo no tenía valor cuando el cache se construyó server-side, no estaba en el cache, y el merge lo ignoraba.

### Nuestro fix (3 cambios, 57 líneas)

1. **`latestFormStateRef`** — un ref que trackea el form state más reciente, actualizado en cada `onChange` (antes y después del server round-trip) y después del fetch inicial
2. **Sync ref→initialState** — en el cleanup del effect (antes de que el componente se oculte) y en el mount (para remounts duros), restauramos el state del ref
3. **Merge de fields faltantes** — iteramos `formData` además de `cachedFormState` para agregar campos que el cache no tenía

### La dificultad real

Este bug toca:
- **React component lifecycle** (Activity/Offscreen, recycling, remounts)
