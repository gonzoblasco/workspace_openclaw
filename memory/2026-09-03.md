## Sesión: memory search fix + cadena de propuestas del taller (10:13 - 10:37)

### Memory search - reactivado
- **Causa raíz del 401:** `memory.search.provider = "ollama"` usaba el provider `ollama` de `models.providers` que apunta a `https://ollama.com` (nube, apiKey) → 401. `nomic-embed-text` es local.
- **Fix (3 cambios aprobados por Gonzo en dashboard, uno a la vez):** `memory.search.provider = "openai-compatible"`, `memory.search.remote.baseUrl = "http://127.0.0.1:11434/v1"`, `memory.search.model = "nomic-embed-text"`.
- **Rebuild:** `openclaw memory index --force` → 514/514 archivos, 4107 chunks, embeddings listos (768 dims), dirty: no. Búsqueda semántica verificada (encontró daily de hoy, score 0.72).
- **Nota:** el restart del gateway (10:26) interrumpió el rebuild en background; al retomar, el índice ya estaba completo.

### Cadena cronológica de propuestas del taller (15 propuestas)
- **Mecánica:** cada update se aplica sobre la anterior; si el target cambió, la propuesta queda `stale` y se re-basa con `propose-update --proposal-dir <generation>` + `apply` (el `revise` no acepta stale). Las stale son estado terminal (no se rechazan ni se cuarentenan) y quedan como registro histórico.
- **Aplicadas (7 skills, commit `ef4e540`):** frontend-ui-engineering (2), github (2), oss-contribution (4 en cadena), agent-orchestration-pipeline-model-arbitration (3 en cadena), workspace-portfolio-hygiene (2 en cadena), code-review-and-quality (1), api-and-interface-design (1).

### Lección
- El taller de skills se maneja por CLI: `openclaw skills workshop list|inspect|apply|reject|propose-update`. Las propuestas `update` encadenadas sobre el mismo target se re-basan con `propose-update` cuando quedan stale.

### Lección
- El review de colección del Skill Workshop tiene límites fijos de diseño (200 skills / 240KB). Para colecciones grandes y curadas, el modo correcto es `propose` (revisión humana), no `auto`.
