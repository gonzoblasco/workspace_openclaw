## Leccion durable - Docker en macOS: Colima y el credsStore huerfano

Al montar Docker para kanam-story-bible (Gonzo eligio Docker Compose), dos trabas concretas que van a repetirse en cualquier proyecto:

1. **`brew install colima docker docker-compose` es suficiente** (no hace falta Docker Desktop). `colima start --cpu 4 --memory 8 --disk 60`. `docker context` queda en `colima`; el socket se publica en `~/.colima/docker.sock`.
2. **`~/.docker/config.json` puede tener `credsStore: desktop` de una instalacion previa de Docker Desktop** -> todo pull falla con `error getting credentials - err: exec: "docker-credential-desktop": executable file not found in $PATH`. Se quita el campo (`credsStore`) y listo; el resto del archivo se conserva. **Backup antes de tocar**: `config.json.bak.$(date +%s)`.
3. **`docker compose` (v2) es un plugin**: si `docker compose version` falla tras instalarlo con brew, agregar `"cliPluginsExtraDirs": ["/opt/homebrew/lib/docker/cli-plugins"]` al config.json.

Regla de proceso: antes de instalar Docker, verificar `docker --version` Y `docker info` (el binario puede existir sin daemon corriendo). Y editar `~/.docker/config.json` con `json.load`/`json.dump` preservando claves, nunca reescribiendolo a mano.

## Leccion durable - SQLAlchemy async: `server_default` rompe en flushes

`MissingGreenlet: greenlet_spawn has not been called` en un PATCH aparentemente inocente. Causa: con `server_default=func.now()` como unico default de `created_at`/`updated_at`, SQLAlchemy no tiene el valor en Python y tras el INSERT hace un SELECT de refresh para poblar el objeto -> IO implicito que en async explota fuera del contexto del greenlet.

Arreglo: definir `default=lambda: datetime.now(UTC)` (y `onupdate=` para `updated_at`) en el mixin, dejando `server_default` solo como respaldo de la base. Es el patron correcto para async: el valor se conoce en Python y no hay roundtrip.

Sintoma secundario a recordar: el error apunta al primer acceso al atributo (`card.updated_at`), no a la escritura, asi que la traza senala el lugar equivocado.

## Leccion durable - un server local lanzado como proceso de sesion de exec esta condenado

Lance el server de kanam-spec con exec en background y el runner lo mato al vencer su **timeout de 30 minutos**. El proceso muere con el turno, y nada lo revive despues de un crash o un reboot. Sintoma: "estaba usando la app, que paso?" con el codigo y el build intactos (`http=000`, puerto libre, sin proceso).

Regla: **cualquier server que el owner vaya a usar (o guardar en un bookmark) se gradúa a LaunchAgent desde el minuto uno**, no cuando se cae. Un proceso de sesion sirve para probar; no para usar.

Al graduarlo, dos cosas que hacen la diferencia entre "funciona en el test" y "funciona de verdad":
1. **`KeepAlive` incondicional** (no `{SuccessfulExit: false}`): una salida limpia por puerto tomado se registra como exito y el job queda muerto sin que nada lo levante.
2. **El comando real en `ProgramArguments`, no detras de un wrapper**: un wrapper con guard "ya esta corriendo -> exit 0" termina el job limpiamente por diseno.

Y antes de `bootstrap`: liberar el puerto del proceso manual, o los dos pelean y uno queda a medio levantar.

## Leccion durable - un grid de N columnas con N+1 hijos

El panel nuevo caia a una fila propia, pegado a la izquierda, con un hueco enorme arriba. Es el sintoma clasico de **agregar un hijo a un CSS grid sin darle columna**. Con `align-items: start` el hueco se agrava: la fila 1 toma la altura del hijo mas alto y el intruso arranca recien abajo de todo eso.

Regla: **al agregar un panel a un layout en grid, contar los hijos ANTES**. Si el diseno pide "dos paneles en la misma columna", envolverlos en un contenedor propio (un solo hijo del grid, con su propio grid interno). Eso deja el layout del contenedor padre intacto y no toca ninguna media query.

Efecto colateral facil de pasar por alto: si las media queries apuntaban a un selector que dejo de ser hijo directo del grid (`.preview { grid-column: 1 / -1 }`), esas reglas **dejan de aplicar en silencio** y el responsive queda roto sin ningun error. Repuntarlas al contenedor nuevo.

Corolario de verificacion: un build verde no prueba nada de layout. Sin plugin de browser, lo maximo verificable es que la regla CSS correcta llegue al bundle servido (no que se vea bien).
