## Sesion: estudio OpenClaw AI in Production (Ken Huang) - Cap 1 (19:32-19:43)

Gonzo inicio sesion de estudio del libro "OpenClaw AI in Production" (Ken Huang, Packt) para prepararse para el puesto AI-Native en OpenSistemas. Misma tecnologia que usamos todos los dias (Gateway, hooks, ACP, Tailscale), ventaja: podemos tocar la tecnologia real en vivo.

### Plan de estudio (metodo)
- Cap por cap (14 caps, 3 partes), en orden (Cap 1 fundamento arquitectonico).
- Por capitulo: resumen ejecutivo + conexion con workspace real + hands-on de verdad + preguntas de entrevista al final de cada parte.
- Prioridad de lectura: Cap 1 primero (base), sin saltar a seguridad (4-5) porque cada cap se apoya en el anterior.

### Cap 1 - The OpenClaw Architecture: Decoupling and Scaling
Temas: Gateway como control plane unico, channel adapters como spokes, plugin extensibility sin tocar core, agent-to-agent routing (7-tier waterfall), horizontal scaling topology, Token Exchange en el boundary.

Conceptos clave:
- **Hub-and-spoke**: Gateway es el control plane (auth, routing, sesiones en un solo proceso). 3 propiedades: seguridad consistente, routing auditable en un lugar, un solo proceso para restart/upgrade/observar a las 2am.
- **bottleneck trade-off**: Gateway es bottleneck potencial -> mantiene request path fino (no hace inference, no maneja tool calls largos, no posee session state FS - eso es del Agent Runtime). Cap 2 detalla el pipeline de 6 fases.
- **gateway.bind** (loopback/lan/tailnet/auto/custom) + gateway.port (default 18789) + gateway.auth. Produccion: bind no-loopback SIEMPRE con auth fuerte. Cambiar bind sin apretar auth = exposicion accidental comun.
- **Startup sidecar sequence**: cada sidecar (hooks, browser, canales, plugins) en su propio try/catch -> Bulkhead al arranque. Parcial > total. Cleanup de stale session locks (30min, PID-alive checks).
- **Channel adapters como spokes**: ChannelPlugin interface minimal (id, meta, config, setup, status, outbound - SIN start/stop). Registry central sin hardcodear implementacion - consulta plugin registry live. Alias (imsg/imessage, internet-relay-chat/irc). 9 canales core + Teams, Matrix, Zalo, etc en extensions/.
- **PluginRegistry** (src/plugins/registry.ts): tools, hooks, typedHooks, channels, providers, gatewayHandlers, httpRoutes, cliRegistrars, services, commands, diagnostics. gatewayHandlers sin duplicacion de method names (dropeado + diagnostic). diagnostics con level warn/error - error es blocking alert en produccion.
- **hookPolicy / allowPromptInjection**: seguridad por plugin en REGISTRATION time, no invocation. Envenenamiento de prompt gobernado por config, no por codigo del plugin.
- **Global registry singleton**: Symbol.for("openclaw.pluginRegistryState") - evita split-registry con multiplas copias del SDK (Jest/Vitest).
- **Routing de 7 tiers** (resolve-route.ts): peer-exact > thread-parent peer > guild+roles > guild > team > account > channel-wide > default. matchedBy loguea el tier - diagnostico de routing sorpresas.
- **Session keys + dmScope**: mainSessionKey para DM collapse. Cambiar dmScope post-deploy = session keys distintas = conversaciones reinician. Decission de deploy-time, no runtime.
- **ACP (Agent Client Protocol)**: sub-agents via AcpSessionManager - identidad de sesion separada del orchestrator, no aparece en history de canal usuario. Reconcilio al arranque (sobrevive restarts).
- **Horizontal scaling**: Gateway en gran parte stateless; session state en OPENCLAW_STATE_DIR (shared persistent volume). Write-lock (session-write-lock.ts) previene writes concurrentes. Para workloads conversationales (bajo rate, alto per-request) el lock de filesystem es adecuado - no necesita Redis/etcd.
- **Bind + reverse proxy**: bind lan + auth trusted-proxy (userHeader + requiredHeaders + trustedProxies validate). trusted_proxy_untrusted_source / trusted_proxy_missing_header.
- **Token Exchange**: OPENCLAW_GATEWAY_TOKEN (long-lived) se cambia en el boundary por session token corto + scope-limited. El long-lived NUNCA viaja al agent runtime. authorizeGatewayConnect + safeEqualSecret (constant-time, anti timing attack) + rate limiting (maxAttempts/windowMs, retryAfterMs).
- **Tailscale identity**: variante de Token Exchange - WhoIs lookup contra control plane de Tailscale valida el header. Mismatch guard -> tailscale_user_mismatch.
