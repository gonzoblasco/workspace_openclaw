**Contexto:** Gonzo quiso explorar cómo usar los agentes/skills de OpenClaw desde VS Code (notebook .ipynb + tasks), no construir una extensión. Investigamos el gateway y su autenticación.

**Hallazgos clave:**

| Aspecto | Detalle |
|---------|---------|
| **Gateway puerto** | 18789 (loopback only, no 3449 default) |
| **Gestión proceso** | macOS LaunchAgent (`ai.openclaw.gateway`) vía launchd |
| **Config archivo** | `~/.openclaw/openclaw.json` |
| **Service env** | `~/.openclaw/service-env/ai.openclaw.gateway.env` |
| **Wrapper script** | `~/.openclaw/service-env/ai.openclaw.gateway-env-wrapper.sh` |
| **Health endpoint** | `http://localhost:18789/health` → `{"ok":true,"status":"live"}` |
| **Tools invoke** | `http://localhost:18789/tools/invoke` (requiere `Authorization: Bearer <token>`) |
| **Auth mode** | `token` (config `gateway.auth.mode: "token"`) referenciando secret store key `OPENCLAW_GATEWAY_TOKEN` |
| **OpenClaw install** | `/opt/homebrew/lib/node_modules/openclaw` (global npm) |
| **Agentes registrados** | 8: `kanam-dev`, `kanam-mind`, `kanam-ops`, `kanam-studio`, `main`, `kanam-critic`, `kanam-auditor`, `kanam-planner` |

**Intentos de autenticación:**
- No había `OPENCLAW_GATEWAY_TOKEN` en environment del proceso (pid 86773)
- Se generó token nuevo con `openclaw secrets store set` pero gateway no lo tomó sin reload
- `openclaw secrets reload` falló por token mismatch (gateway corriendo con token viejo)
- Se intentó `launchctl bootout` para reiniciar servicio → gateway se reinició solo vía launchd
- Token generado se eliminó después (`openclaw secrets store rm OPENCLAW_GATEWAY_TOKEN --yes`)

**Estado final:** Gateway vivo en 18789, health ok, config intacta referenciando token en store (pero store vacío). Próximo reinicio del servicio fallaría auth salvo que se cambie `gateway.auth.mode` a `"none"` o se pueble el store.

**Decisión de Gonzo:** "no quiero continuar, quitemos los cambios introducidos" - se revirtió el token generado, no se crea notebook.
