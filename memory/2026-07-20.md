# 2026-07-20 — Modelos Ollama Cloud, workflow de reasoning, fix de truncamiento

## Sesión: Evaluación de modelos y configuración de default

### Modelos evaluados (11 modelos)
- **nemotron-3-super:cloud** (era el default, tier 2, truncaba respuestas largas)
- **deepseek-v4-flash:cloud** (nuevo default, tier 2, 1M contexto, 3 thinking modes)
- **deepseek-v4-pro:cloud** (tier 4, frontier, caro)
- **minimax-m3:cloud** (tier 3, 1M contexto, multimodal, browsing líder)
- **glm-5.2:cloud** (tier 3, coding-agent líder abierto)
- **kimi-k2.7-code:cloud** (tier 2, coding agentic eficiente)
- **qwen3.5:cloud** / **qwen3.5:397b-cloud** (tier 1-2, todo terreno)
- **gemma4:cloud** / **gemma4:31b-cloud** (tier 0-1, ligero)
- **qwen3-coder:480b-cloud** (no disponible en Ollama Cloud)

### Decisión final
- **Default:** `deepseek-v4-flash:cloud` con **reasoning medium**
- **Workflow de reasoning:** Kanam filtra cada tarea y recomienda subir/bajar; Gonzo decide si acepta o dice "ignorar recomendación"
- **Fix aplicado:** `maxTokens` subido de N/A a 65536 para deepseek-v4-flash:cloud (antes truncaba respuestas largas como ADRs completos)
- **Nemotron-3-Super descartado como default** porque truncaba incluso con maxTokens=65536 (el modelo mismo tiene límite de salida)

### Prueba real de comparación
- Mismo prompt (ADR de auto-respuesta inteligente) corrido con reasoning off, medium, y maximum
- **Maximum ganó en calidad:** no solo dio la solución, sino que encontró 5 problemas que el ADR no cubría (pesos fijos del re-ranker, feedback loop desconectado, billing frágil, refresh de tokens, race conditions en workers)
- **Sin reasoning:** solución correcta pero sin crítica
- **Medium:** punto medio óptimo para uso diario
