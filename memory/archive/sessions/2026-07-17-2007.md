## 🎯 Areas de Mejora (Action Plan)

### 1. ADR as Commit — Gap: -4 puntos

**Problema actual:**
- Usas "feat: [description]" sin referencia a un ADR existente o documento creado primero
- En repos donde ya había commits previos con decisiones documentadas, tú sigues el patrón de feature commit directo
- Faltan commits que expliquen **por qué** se tomó esa decisión arquitectónica

**Acciones específicas:**

```bash
# 1. Antes de cada feature commit, crea o referenciá un ADR primero:
git log --oneline | head -10  # Verify history
git branch -a                # Check for open branches

# Si hay una nueva feature importante:
echo "### New decision context:" > docs/ADRs/ADR-NEW-xxx.md
echo "Context: [what problem]" >> docs/ADRs/ADR-NEW-xxx.md
echo "Decision: [what we decided]" >> docs/ADRs/ADR-NEW-xxx.md
echo "Consequences: [trade-offs]" >> docs/ADRs/ADR-NEW-xxx.md

# Commit with ADR reference:
git add docs/ADRs/ADR-NEW-xxx.md
git commit -m "adr: Document trade-offs for X approach (see ADR-NEW-xxx)"

# Then implement and commit feature:
git add src/ ...
git commit -m "feat: Implement X as per ADR-NEW-xxx"
```

**Target:** 10/10 → Create ADR first for every major architectural decision.
