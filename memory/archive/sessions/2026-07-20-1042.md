# ADR-024: Sistema de Auto-Respuesta Inteligente con RAG + Auto-Learn + Billing

**Estado:** Aprobado  
**Fecha:** 2026-07-20  
**Decisores:** Gonzo (PO/Arquitecto), Kanam (Arquitecta)  
**Contexto:** SoporteML v2 — SaaS multi-tenant para vendedores de Mercado Libre  

---

## Contexto

SoporteML recibe preguntas de compradores de Mercado Libre a través de webhooks. Cada tenant tiene 1-N cuentas MeLi vinculadas via OAuth2. El sistema debe:

1. **Clasificar** cada pregunta como rutinaria (auto-responder con IA) o compleja (derivar a humano).
2. **Responder** usando RAG sobre una Knowledge Base vectorial (pgvector, 1536d).
3. **Auto-aprender** de preguntas históricas al conectar una cuenta nueva.
4. **Respetar** rate limiting de MeLi (300 req/min) con cola + retry.
5. **Facturar** por suscripción con Mercado Pago, límites por plan.

### b) Re-Ranker sin Servicio Externo Pago

**Decisión:** Re-ranker basado en **Cross-Encoder local con ONNX Runtime** + **heuristic scoring** como fallback.

```typescript
// supabase/functions/_shared/reranker.ts

// Opción 1: Cross-Encoder local con ONNX (recomendada)
// Modelo: sentence-transformers/ms-marco-MiniLM-L-6-v2 (exportado a ONNX)
// Tamaño: ~90MB, corre en Edge Function con warm starts

import { InferenceSession, Tensor } from 'onnxruntime-node';

interface RerankResult {
  chunkId: string;
  similarity: number;    // cosine similarity original
  rerankScore: number;   // score del cross-encoder
  combinedScore: number; // weighted final score
}

export async function rerankWithCrossEncoder(
  query: string,
  chunks: Array<{ id: string; text: string; similarity: number }>
): Promise<RerankResult[]> {
  const session = await InferenceSession.create(
    '/models/ms-marco-MiniLM-L-6-v2.onnx'
  );

  const pairs = chunks.map(c => [query, c.text]);
  
  // Tokenizar y correr inferencia en batch
  const scores = await Promise.all(
    pairs.map(async ([q, doc]) => {
      const inputs = tokenizePair(q, doc);
      const results = await session.run(inputs);
      return results['logits'].data[0]; // scalar score
    })
  );

  // Normalizar scores a [0, 1]
  const min = Math.min(...scores);
  const max = Math.max(...scores);
  const normalized = scores.map(s => (max - min === 0) ? 0.5 : (s - min) / (max - min));

  return chunks.map((chunk, i) => ({
    chunkId: chunk.id,
    similarity: chunk.similarity,
    rerankScore: normalized[i],
    combinedScore: 0.3 * chunk.similarity + 0.7 * normalized[i],
  })).sort((a, b) => b.combinedScore - a.combinedScore);
}

// Opción 2: Heuristic Re-ranker (fallback, sin dependencias externas)
export function rerankHeuristic(
  query: string,
  chunks: Array<{
    id: string;
    text: string;
    similarity: number;
    metadata: {
      qualityScore?: number;
      usageCount?: number;
      sourceType?: string;
    };
  }>
): RerankResult[] {
  const queryTerms = query.toLowerCase().split(/\s+/).filter(t => t.length > 3);
  const stopWords = new Set(['para', 'como', 'que', 'con', 'por', 'del', 'las', 'los']);

  return chunks.map(chunk => {
    const chunkLower = chunk.text.toLowerCase();
    
    // 1. Exact term matching bonus
    const matchingTerms = queryTerms.filter(t => !stopWords.has(t) && chunkLower.includes(t));
    const termMatchRatio = matchingTerms.length / Math.max(queryTerms.length, 1);
    
    // 2. Position bias (earlier chunks in document get slight bonus)
    const positionScore = 1.0; // neutral, could be refined
    
    // 3. Quality score from feedback
    const qualityScore = chunk.metadata.qualityScore ?? 0.5;
    
    // 4. Recency / usage bonus
    const usageBonus = Math.min(chunk.metadata.usageCount ?? 0, 10) / 10;
    
    // 5. Source type weight
    const sourceWeights: Record<string, number> = {
      product_ficha: 1.2,    // fichas de producto = más relevantes
      previous_answer: 1.1,  // respuestas previas = relevantes
      faq: 1.0,
      template: 0.8,
      manual: 0.7,
    };
    const sourceWeight = sourceWeights[chunk.metadata.sourceType ?? 'faq'] ?? 1.0;
    
    // Combined heuristic score
    const rerankScore = (
      0.35 * termMatchRatio +
      0.25 * qualityScore +
      0.20 * chunk.similarity +
      0.10 * usageBonus +
      0.10 * sourceWeight
    );

    return {
      chunkId: chunk.id,
      similarity: chunk.similarity,
      rerankScore: Math.min(rerankScore, 1.0),
      combinedScore: 0.3 * chunk.similarity + 0.7 * Math.min(rerankScore, 1.0),
    };
  }).sort((a, b) => b.combinedScore - a.combinedScore);
}
```

```typescript
    .from('billing.subscriptions')
    .select('*')
    .eq('tenant_id', tenantId)
    .single();

  if (subscription.auto_responses_used >= 
      (await getPlanLimit(subscription.plan_id, 'max_auto_responses'))) {
    // Escalar a humano automáticamente
    await escalateToHuman(questionId, 'billing_limit');
    return new Response(JSON.stringify({ action: 'escalated', reason: 'billing_limit' }));
  }

  // 3. Clasificar pregunta
  const classification = await classifyQuestion(question, tenantId);
  
  await supabase.from('auto_response.classifications').insert({
    tenant_id: tenantId,
    question_id: questionId,
    category: classification.category,
    confidence: classification.confidence,
    model_used: classification.modelUsed,
    features: classification.features,
    classifier_version: 'v1.0.0',
    latency_ms: classification.latencyMs,
  });

  if (classification.category === 'compleja') {
    await escalateToHuman(questionId, 'complex_question');
    return new Response(JSON.stringify({ action: 'escalated', reason: 'complex' }));
  }

  // 4. RAG pipeline
  const kbResults = await searchKB(question.question_text, tenantId, {
    productId: question.meli_product_id,
    limit: 10, // fetch 10, rerank top 3
  });

  const reranked = rerankHeuristic(question.question_text, kbResults);
  const topChunks = reranked.slice(0, 3);

  // 5. Generar respuesta
  const response = await generateResponse({
    question: question.question_text,
    context: topChunks.map(c => c.text),
    tenantId,
    productId: question.meli_product_id,
  });

  // 6. Confidence check
  if (response.confidence < 0.7) {
    await escalateToHuman(questionId, 'low_confidence');
    return new Response(JSON.stringify({ action: 'escalated', reason: 'low_confidence' }));
  }

  // 7. Guardar respuesta
  const { data: savedResponse } = await supabase
    .from('auto_response.responses')
    .insert({
      tenant_id: tenantId,
      question_id: questionId,
      classification_id: classification.id,
      content: response.content,
      source: 'auto_ia',
      rag_context: topChunks.map(c => ({
        chunk_id: c.id,
        similarity: c.similarity,
        rerank_score: c.rerankScore,
        source: c.metadata?.sourceType,
      })),
      pipeline_confidence: response.confidence,
      status: 'pending',
    })
    .select()
    .single();

  // 8. Encolar envío a MeLi (rate limited)
  await supabase.from('auto_response.meli_queue').insert({
    tenant_id: tenantId,
    meli_account_id: question.meli_account_id,
    action: 'send_answer',
    payload: {
      question_id: question.meli_question_id,
      answer_text: response.content,
      response_id: savedResponse.id,
    },
    priority: 5,
  });

  // 9. Actualizar contador de billing
  await supabase.rpc('increment_auto_response_usage', {
    p_tenant_id: tenantId,
  });

  return new Response(JSON.stringify({ 
    action: 'auto_responded', 
    responseId: savedResponse.id,
    confidence: response.confidence,
  }));
});
```

### c) Estrategia de Caché para API de MeLi

**Decisión:** Caché de 3 capas con TTLs diferenciados.

```typescript
// supabase/functions/_shared/meli-cache.ts

interface CacheConfig {
  ttl: number;        // TTL en segundos
  staleTtl: number;   // TTL para stale-while-revalidate
  invalidateOn: string[]; // eventos que invalidan
}

const CACHE_CONFIGS: Record<string, CacheConfig> = {
  // Datos de producto: cambian poco, cache largo
  'get_product': {
    ttl: 3600,           // 1 hora
    staleTtl: 86400,     // 24h stale
    invalidateOn: ['product_updated', 'product_price_changed'],
  },
  // Preguntas: frescura importante
  'get_questions': {
    ttl: 60,             // 1 minuto
    staleTtl: 300,       // 5 min stale
    invalidateOn: ['question_answered', 'new_question'],
  },
  // Categorías: casi estático
  'get_categories': {
    ttl: 86400,          // 24 horas
    staleTtl: 604800,    // 7 días stale
    invalidateOn: [],
  },
  // Token de acceso: cache corto pero seguro
  'get_access_token': {
    ttl: 21600,          // 6 horas (token dura 6h)
    staleTtl: 0,         // no stale
    invalidateOn: ['token_refreshed'],
  },
};

// Capa 1: Memoria (Edge Function warm start)
// Capa 2: Supabase (KV table)
// Capa 3: Stale-while-revalidate

export class MeliCache {
  private memoryCache = new Map<string, { data: any; expires: number }>();
  private supabase: SupabaseClient;

  constructor(supabase: SupabaseClient) {
    this.supabase = supabase;
  }

  async get<T>(key: string, config: CacheConfig): Promise<T | null> {
    const cacheKey = `meli:${key}`;
    
    // 1. Memory cache (fastest)
    const mem = this.memoryCache.get(cacheKey);
    if (mem && mem.expires > Date.now()) {
      return mem.data as T;
    }

    // 2. Supabase cache
    const { data: db } = await this.supabase
      .from('cache.meli_cache')
      .select('*')
      .eq('cache_key', cacheKey)
      .single();

    if (db) {
      const age = (Date.now() - new Date(db.updated_at).getTime()) / 1000;
      
      if (age < config.ttl) {
        // Fresh: update memory + return
        this.memoryCache.set(cacheKey, { data: db.data, expires: Date.now() + config.ttl * 1000 });
        return db.data as T;
      }
      
      if (age < config.ttl + config.staleTtl) {
        // Stale but acceptable: return stale + trigger revalidation async
        this.revalidateAsync(cacheKey, key, config);
        return db.data as T;
      }
    }

    // 3. Miss: fetch fresh
    return null;
  }

  async set(key: string, data: any, config: CacheConfig): Promise<void> {
    const cacheKey = `meli:${key}`;
    
    // Memory
    this.memoryCache.set(cacheKey, { 
      data, 
      expires: Date.now() + config.ttl * 1000 
    });
    
    // Supabase
    await this.supabase.from('cache.meli_cache').upsert({
      cache_key: cacheKey,
      data,
      ttl_seconds: config.ttl,
      updated_at: new Date().toISOString(),
    });
  }

  async invalidate(patterns: string[]): Promise<void> {
    for (const pattern of patterns) {
      // Memory
      for (const key of this.memoryCache.keys()) {
        if (key.includes(pattern)) this.memoryCache.delete(key);
      }
      
      // Supabase
      await this.supabase
        .from('cache.meli_cache')
        .delete()
        .like('cache_key', `%${pattern}%`);
    }
  }

  private async revalidateAsync(cacheKey: string, key: string, config: CacheConfig) {
    // Edge Function se ejecuta en background
    try {
      const fresh = await fetchFromMeli(key);
      await this.set(key, fresh, config);
    } catch {
      // Stale data is better than no data
    }
  }
}

// Tabla de caché en Supabase
const CACHE_TABLE_SQL = `
CREATE TABLE IF NOT EXISTS cache.meli_cache (
  cache_key     TEXT PRIMARY KEY,
  data          JSONB NOT NULL,
  ttl_seconds   INTEGER NOT NULL,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Cleanup job: delete expired entries
CREATE INDEX idx_meli_cache_expired ON cache.meli_cache(updated_at) 
  WHERE updated_at < now() - (ttl_seconds || ' seconds')::interval;
`;
```

```typescript
import { createClient } from 'https://esm.sh/@supabase/supabase-js@2.39.0';

serve(async (req) => {
  const webhook = await req.json();
  const idempotencyKey = req.headers.get('x-idempotency-key') || 
    `meli:${webhook.resource}:${webhook.topic}:${webhook.id}`;

  const supabase = createClient(
    Deno.env.get('SUPABASE_URL')!,
    Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!
  );

  // 1. Idempotency check (evita procesar el mismo evento dos veces)
  const { data: existing } = await supabase
    .from('events.idempotency')
    .select('id')
    .eq('idempotency_key', idempotencyKey)
    .maybeSingle();

  if (existing) {
    return new Response(JSON.stringify({ status: 'duplicate' }), { status: 200 });
  }

  // 2. Outbox pattern: primero registrar el evento, después procesar
  const { data: event } = await supabase
    .from('events.outbox')
    .insert({
      idempotency_key: idempotencyKey,
      source: 'meli_webhook',
      event_type: webhook.topic,
      payload: webhook,
      status: 'pending',
    })
    .select()
    .single();

  // 3. Responder inmediatamente a MeLi (200 OK)
  // El procesamiento real ocurre en segundo plano
  const response = { 
    status: 'accepted', 
    event_id: event.id,
    message: 'Evento recibido, procesando...'
  };

  // 4. Procesar asincrónicamente (no bloquear el webhook)
  EdgeFunction.waitUntil(processEvent(event.id, supabase));

  return new Response(JSON.stringify(response), { 
    status: 200,
    headers: { 'Content-Type': 'application/json' }
  });
});

async function processEvent(eventId: string, supabase: SupabaseClient) {
  try {
    const { data: event } = await supabase
      .from('events.outbox')
      .update({ status: 'processing', processing_at: new Date().toISOString() })
      .eq('id', eventId)
      .select()
      .single();

    switch (event.event_type) {
      case 'questions':
        await handleNewQuestion(event.payload, supabase);
        break;
      case 'questions/answered':
        await handleQuestionAnswered(event.payload, supabase);
        break;
      case 'products':
        await handleProductUpdate(event.payload, supabase);
        break;
    }

    await supabase
      .from('events.outbox')
      .update({ status: 'completed', completed_at: new Date().toISOString() })
      .eq('id', eventId);

  } catch (error) {
    await supabase
      .from('events.outbox')
      .update({ 
        status: 'failed', 
        error_message: error.message,
        retry_count: supabase.rpc('increment_retry_count', { p_event_id: eventId }),
      })
      .eq('id', eventId);
  }
}
```

### Rate Limiting + Cola con Retry Exponencial

```typescript
// supabase/functions/meli-queue-worker/index.ts

import { serve } from 'https://deno.land/std@0.208.0/http/server.ts';
import { createClient } from 'https://esm.sh/@supabase/supabase-js@2.39.0';

// Token bucket rate limiter
class MeliRateLimiter {
  private buckets = new Map<string, { tokens: number; lastRefill: number }>();
  
  // MeLi: 300 req/min = 5 req/sec
  private readonly MAX_TOKENS = 300;
  private readonly REFILL_RATE = 300 / 60; // tokens per second
  private readonly REFILL_INTERVAL = 1000; // ms

  async acquire(accountId: string): Promise<number> {
    const now = Date.now();
    let bucket = this.buckets.get(accountId);
    
    if (!bucket) {
      bucket = { tokens: this.MAX_TOKENS, lastRefill: now };
      this.buckets.set(accountId, bucket);
    }

    // Refill tokens
    const elapsed = (now - bucket.lastRefill) / 1000;
    bucket.tokens = Math.min(
      this.MAX_TOKENS,
      bucket.tokens + elapsed * this.REFILL_RATE
    );
    bucket.lastRefill = now;

    if (bucket.tokens >= 1) {
      bucket.tokens -= 1;
      return 0; // no wait
    }

    // Calculate wait time
    const waitMs = Math.ceil((1 - bucket.tokens) / this.REFILL_RATE * 1000);
    return waitMs;
  }
}

const rateLimiter = new MeliRateLimiter();

serve(async (req) => {
  const supabase = createClient(
    Deno.env.get('SUPABASE_URL')!,
    Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!
  );

  // Procesar items de la cola
  const { data: queueItems } = await supabase
    .from('auto_response.meli_queue')
    .select('*')
    .in('status', ['queued', 'failed'])
    .lt('next_retry_at', new Date().toISOString())
    .order('priority', { ascending: true })
    .order('scheduled_at', { ascending: true })
    .limit(10);

  if (!queueItems?.length) {
    return new Response(JSON.stringify({ processed: 0 }));
  }

  let processed = 0;
  for (const item of queueItems) {
    // Rate limit check
    const waitMs = await rateLimiter.acquire(item.meli_account_id);
    if (waitMs > 0) {
      // Re-schedule for later
      await supabase
        .from('auto_response.meli_queue')
        .update({ scheduled_at: new Date(Date.now() + waitMs).toISOString() })
        .eq('id', item.id);
      continue;
    }

    // Mark as processing
    await supabase
      .from('auto_response.meli_queue')
      .update({ status: 'processing', processing_at: new Date().toISOString() })
      .eq('id', item.id);

    try {
      // Execute the action
      const result = await executeMeliAction(item, supabase);
      
      await supabase
        .from('auto_response.meli_queue')
        .update({ 
          status: 'completed', 
          completed_at: new Date().toISOString() 
        })
        .eq('id', item.id);
      
      processed++;
    } catch (error) {
      const retryCount = item.retry_count + 1;
      const nextRetry = calculateNextRetry(retryCount);
      
      await supabase
        .from('auto_response.meli_queue')
        .update({
          status: retryCount >= item.max_retries ? 'failed' : 'failed',
          retry_count: retryCount,
          last_error: error.message,
          next_retry_at: nextRetry.toISOString(),
        })
        .eq('id', item.id);
    }
  }

  return new Response(JSON.stringify({ processed }));
});

function calculateNextRetry(retryCount: number): Date {
  // Exponential backoff: 1s, 2s, 4s, 8s, 16s, 32s
  const delayMs = Math.min(1000 * Math.pow(2, retryCount), 60000);
  const jitter = Math.random() * 1000; // add jitter
  return new Date(Date.now() + delayMs + jitter);
}
```

```typescript
    const ficha = await generateProductFicha(productData, productQuestions);
    
    // Guardar ficha
    const { data: savedFicha } = await supabase
      .from('auto_response.product_fichas')
      .upsert({
        tenant_id: tenantId,
        meli_product_id: productId,
        title: productData.title,
        category_id: productData.category_id,
        category_path: productData.category_path,
        attributes: productData.attributes,
        ficha_content: ficha.content,
        ficha_embedding: ficha.embedding, // vector(1536)
        source: 'auto_learn',
        last_synced_at: new Date().toISOString(),
      })
      .select()
      .single();

    // 5. Indexar chunks de la ficha en KB
    const chunks = chunkText(ficha.content, 512); // 512 char chunks
    for (const chunk of chunks) {
      const embedding = await generateEmbedding(chunk);
      
      await supabase
        .from('auto_response.kb_chunks')
        .insert({
          tenant_id: tenantId,
          source_type: 'product_ficha',
          source_id: savedFicha.id,
          meli_product_id: productId,
          chunk_text: chunk,
          chunk_embedding: embedding,
          chunk_metadata: {
            language: 'es',
            word_count: chunk.split(/\s+/).length,
            section: detectSection(chunk),
            is_auto_generated: true,
          },
        });
    }

    // 6. Indexar preguntas respondidas como ejemplos
    for (const q of productQuestions) {
      if (q.answer_text) {
        const qEmbedding = await generateEmbedding(
          `P: ${q.question_text}\nR: ${q.answer_text}`
        );
        
        await supabase
          .from('auto_response.kb_chunks')
          .insert({
            tenant_id: tenantId,
            source_type: 'previous_answer',
            meli_product_id: productId,
            chunk_text: `Pregunta: ${q.question_text}\nRespuesta: ${q.answer_text}`,
            chunk_embedding: qEmbedding,
            chunk_metadata: {
              language: 'es',
              is_auto_generated: true,
              original_question_id: q.meli_question_id,
            },
          });
      }
    }
  }

  // 7. Marcar como procesado
  await supabase
    .from('meli_accounts')
    .update({ auto_learn_completed: true, auto_learn_at: new Date().toISOString() })
    .eq('id', meliAccountId);

  return new Response(JSON.stringify({ 
    status: 'completed',
    products_processed: Object.keys(byProduct).length,
    questions_processed: questions.length,
  }));
});
```

## Consecuencias

### Positivas
1. **Aislamiento total multi-tenant:** RLS por tenant_id en todas las tablas + funciones SECURITY DEFINER con filtro explícito.
2. **Sin dependencias externas pagas:** Re-ranker heurístico + ONNX local. El clasificador usa el mismo modelo LLM que ya tenemos (DeepSeek).
3. **Consistencia eventual manejable:** Outbox + idempotency keys + reconciliation job cubren los casos de webhook duplicado, fallo temporal, y orden de llegada.
4. **Caché agresiva:** 3 capas con stale-while-revalidate minimizan llamadas a MeLi. TTLs diferenciados por tipo de dato.
5. **Rate limiting robusto:** Token bucket + cola con prioridad + retry exponencial con jitter.
6. **Feedback loop cerrado:** Cada respuesta tiene su clasificación, contexto RAG, y feedback del vendedor. Permite mejorar el clasificador y el re-ranker con datos reales.

### Negativas
1. **Complejidad operativa:** 7 nuevas tablas, 4 Edge Functions, 1 cron job de reconciliation, 1 cron job de cleanup de caché.
2. **Costo de embeddings:** Cada pregunta entrante requiere 1 embedding (clasificación) + 1 embedding (búsqueda KB). ~2 llamadas al modelo de embeddings por pregunta. Con DeepSeek embeddings es económico pero hay que monitorear.
3. **Latencia del pipeline completo:** Clasificación → RAG → Re-rank → Generación → Encolar. ~3-5 segundos total. Aceptable para un sistema de auto-respuesta (no es tiempo real).
4. **ONNX en Edge Functions:** El modelo de cross-encoder (~90MB) necesita warm starts. En cold starts puede agregar 1-2 segundos. Alternativa: mantener el re-ranker heurístico como default y el cross-encoder como upgrade.

### Riesgos y Mitigaciones

| Riesgo | Mitigación |
|--------|-----------|
| Embedding model cambia (1536d → otro) | Migración con `ALTER TABLE ... ALTER COLUMN ... TYPE VECTOR(n)` + re-index |
| MeLi cambia rate limits | Configurable por variable de entorno, no hardcodeado |
| Tenant malicioso abusa del sistema | Rate limiting por tenant + billing limits + alertas de uso anómalo |
| Webhook de MeLi llega desordenado | Idempotency keys + updated_at en preguntas para detectar stale updates |
| Feedback loop no se usa | Dashboard de analytics muestra impacto del feedback en accuracy |

## Alternativas Descartadas

### 1. Re-ranker con API paga (Cohere Rerank, Jina Rerank)
**Descartado por:** Costo recurrente. Para un SaaS con márgenes ajustados, cada llamada de re-rank suma. El heurístico + ONNX local cubre el caso de uso sin costo marginal.

### 2. Redis para caché
**Descartado por:** Overhead operativo. Supabase ya tiene PostgreSQL. La tabla `cache.meli_cache` con upsert + cleanup periódico es suficiente para el volumen esperado (< 1000 tenants, < 100 req/min por tenant).

### 3. Kafka / RabbitMQ para cola de mensajes
**Descartado por:** Overkill. La tabla `auto_response.meli_queue` con índices en status + scheduled_at funciona como cola de base de datos. PostgreSQL puede manejar millones de filas con los índices correctos. Si escala a > 100k msg/día, se puede migrar a pgmq o RabbitMQ.

### 4. Clasificador con modelo separado (BERT clasificador)
**Descartado por:** El mismo LLM (DeepSeek) que genera respuestas puede clasificar. Un solo modelo para ambas tareas simplifica la arquitectura. El clasificador basado en LLM con prompt engineering + features estructuradas es suficientemente preciso para el caso de uso.

### 5. Webhook síncrono (esperar a procesar antes de responder 200)
**Descartado por:** MeLi espera 200 OK rápido. Procesar todo síncrono timeout. El patrón outbox + 200 inmediato + procesamiento async es el estándar para webhooks.

### 6. Caché distribuida (Redis Cluster, Memcached)
**Descartado por:** La caché en memoria de la Edge Function + Supabase cubre el caso. Si el sistema escala a múltiples regiones, se puede agregar Redis como capa compartida.
