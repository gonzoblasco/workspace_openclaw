## Workflows de skills del workspace

### `workflow-product-discovery`
**Cuándo:** Tenés una idea difusa y querés llegar a una definición de producto clara. Desde "che, debería hacer algo con X" hasta BRIEF + EVALUATION + DEFINITION.

**Cuándo NO:** Ya sabés exactamente qué vas a construir y tenés el spec. Ahí saltá directo a scaffold.

**Ejemplo:** "Quiero hacer una herramienta para auditar accesibilidad" → product discovery primero.

---

### `workflow-build-scaffold`
**Cuándo:** Ya tenés la definición del producto y querés generar el proyecto desde cero con estructura, config, tooling, CI/CD, todo.

**Cuándo NO:** El proyecto ya existe y solo necesitás agregar una feature. Ahí es task execution directo.

**Ejemplo:** Acabás de definir `accessible-ui` → build scaffold para crear el repo con todo configurado.

---

### `workflow-task-execution`
**Cuándo:** Tenés un proyecto existente y una tarea concreta: implementar una feature, fixear un bug, refactorizar algo.

**Cuándo NO:** Estás en fase de definición o querés documentar algo existente.

**Ejemplo:** "Agregar un Combobox a accessible-ui" → task execution.

---

### `workflow-review-quality`
**Cuándo:** Antes de mergear un PR, o cuando querés una auditoría de código existente. Revisa calidad, seguridad, performance, buenas prácticas.

**Cuándo NO:** El código todavía no está escrito (usá task execution primero) o es un review casual de un snippet chico.

**Ejemplo:** "Revisame este PR antes de mergear" o "auditá la seguridad de este endpoint".

---

### `workflow-pre-deploy-qa`
**Cuándo:** Estás por deployar a producción y querés una validación completa: build, rutas, SEO, API, performance, lighthouse, seguridad, cleanup.

**Cuándo NO:** Es un cambio chico en dev y no va a prod todavía.

**Ejemplo:** "Voy a deployar la nueva versión de create-stack-next, pasale el checklist pre-deploy."

---

### `workflow-tech-docs`
**Cuándo:** Necesitás documentación técnica: ADRs, README, API docs, CHANGELOG, guías de arquitectura.

**Cuándo NO:** Es documentación de producto o contenido narrativo.

**Ejemplo:** "Documentá la decisión de usar Biome en vez de ESLint" → ADR. "Escribime el README del proyecto."

---

### `workflow-narrative-content`
**Cuándo:** Querés escribir ficción: novelas, cuentos, planificación narrativa, worldbuilding.

**Cuándo NO:** Es documentación técnica, contenido de producto, o copywriting.

**Ejemplo:** "Quiero arrancar esa novela de ciencia ficción que tengo en mente."

---

### `workflow-accessibility-studio`
**Cuándo:** Diseño, auditoría, autofix o validación de accesibilidad. Cubre todo el ciclo: desde diseñar un componente accesible hasta auditar uno existente.

**Cuándo NO:** Es un tema no relacionado a a11y.

**Ejemplo:** "Auditá la accesibilidad de este modal" o "diseñame un DatePicker accesible."

---

### `workflow-oss-contribution`
**Cuándo:** Querés contribuir a un repo externo (shadcn/ui, TanStack, Vercel, etc.). Evalúa el repo, encuentra issues, prepara el PR, maneja el fork.

**Cuándo NO:** Es tu propio proyecto o un fork que ya tenés configurado.

**Ejemplo:** "Quiero mandar un PR a TanStack Router para mejorar los types de search params."

---

### `workflow-vibe-code-cleanup`
**Cuándo:** Tenés código generado por IA (vibe coding) que necesita limpieza para producción: diagnosticar, refactorizar, endurecer.

**Cuándo NO:** El código fue escrito a mano o ya pasó por review.

**Ejemplo:** "Generé esto con Claude y está functional pero hecho un desastre, limpiámelo."

---

### `workflow-session-lifecycle`
**Cuándo:** Arrancás o cerrás una sesión de trabajo en un proyecto. Setup de contexto, handoff, cierre ordenado.

**Cuándo NO:** Es una consulta rápida o no estás trabajando en un proyecto específico.

**Ejemplo:** "Arrancamos sesión de a11y-fixer" o "cerremos la sesión de hoy con handoff."

```
  ¿Es ficción? → narrative-content
  ¿Es accesibilidad? → accessibility-studio
  ¿Es contribución externa? → oss-contribution

  ¿Es pre-merge? → review-quality
  ¿Es pre-deploy? → pre-deploy-qa
  ¿Es setup/cierre de sesión? → session-lifecycle
```
