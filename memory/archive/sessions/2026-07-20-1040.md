## 🔌 Primero: ¿en qué nivel se enciende el razonamiento?

En los modelos de Ollama Cloud que vienen con **thinking modes** (como DeepSeek-V4 y familia Qwen3), el razonamiento se controla vía un **flag en el chat template** o mediante un **prefijo especial en el prompt**. No es un "nivel" que subas en la UI como un slider, sino que:

- **Para activar thinking**: normalmente incluís un token especial como `<think>` o usás una plantilla que lo active.
- En OpenClaw, **no hay un toggle público aún** para esto (a menos que lo hayas configurado en tu profile o vía skill).
- Por **defecto**, muchos de estos modelos vienen con **thinking OFF** (respuesta directa) para optimizar velocidad y costo.
- Para activarlo, tendrías que:
  1. Usar un **model override específico** que force thinking (ej: una variante del modelo con `-think` en el nombre), **o**
  2. Modificar el **chat template** vía configuración del gateway (avanzado), **o**
  3. Incluir manualmente un **prefijo como "Let me think step by step:"** en tu prompt (menos confiable, depende del modelo).

> 🔎 **Conclusión**: si no hiciste nada especial, **estás corriendo sin thinking mode activado**. Activarlo **sí aumenta consumo de tokens y latency**, pero no tanto como subir de tier (por ejemplo, de Nemotron a M3).

## ¿Por qué trunca?

El truncamiento no es del modelo en sí, sino de **cómo OpenClaw maneja la salida**. Posibles causas:

1. **Límite de tokens de salida por defecto** — OpenClaw tiene un `max_tokens` por respuesta (probablemente configurado bajo, tipo 4096 o 8192). Cuando el modelo genera más, corta.
2. **Nemotron-3-Super tiene 12B activos de 120B totales** — puede que el gateway esté limitando la salida para mantener latencia baja.
3. **El modelo no está configurado para streaming largo** — si la respuesta es muy larga (ej: un spec completo, un análisis detallado), el gateway corta antes de que termine.
