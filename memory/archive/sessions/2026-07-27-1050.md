## LangGraph

Es un framework de LangChain para construir agentes como grafos de estado. La idea es buena: modelás el flujo de trabajo como nodos (pasos) y edges (transiciones), con estado persistente entre pasos.

**Lo bueno:** te da control fino sobre el flujo. Si necesitás branching complejo, ciclos, checkpoints para retomar — LangGraph lo resuelve bien.

**Lo que no me cierra:** es parte del ecosistema LangChain, que tiene fama de sobre-ingeniería, abstracciones que se rompen, y churn constante. Mucho boilerplate para cosas que podrías hacer con funciones puras.

**¿Nos serviría?** Para flujos multi-step con branching complejo tipo "si el PR falla CI, analizar error, sugerir fix, esperar confirmación, commitear". Pero con lo que ya tenemos (subagentes, handoffs, skills) cubrimos el 80% de eso sin depender de LangChain.

## AutoGen (Microsoft)

Framework para agentes conversacionales que se pasan mensajes entre sí. La idea es que varios "agentes" especializados conversan para resolver un problema.

**Lo bueno:** el patrón de multi-agente conversacional es potente para tareas que requieren debate o revisión cruzada. Tipo: un agente escribe código, otro lo revisa, otro escribe tests, y conversan hasta que están de acuerdo.

**Lo que no me cierra:** mucho overhead de mensajes. Los agentes "conversan" en texto natural, lo cual es lento, caro, y propenso a alucinaciones en cadena. Además el API cambió bastante entre versiones.

**¿Nos serviría?** El patrón de "agente revisor" ya lo tenemos con subagentes y el skill de review-quality. La diferencia es que nosotros no hacemos que los agentes "conversen" en lenguaje natural — usamos handoffs estructurados, que es más eficiente. AutoGen sería overkill.

## CrewAI

Framework para orquestar "crews" de agentes con roles definidos (researcher, writer, reviewer) que trabajan en tareas secuenciales o jerárquicas.

**Lo bueno:** la metáfora de "crew" es intuitiva. Definís roles, tasks, y un proceso (sequential o hierarchical). Bueno para pipelines tipo research → write → review.

**Lo que no me cierra:** es más rígido de lo que parece. Los procesos hierarchical dependen de un "manager agent" que decide qué hacer, lo cual es lento y caro. Además, como AutoGen, sufre del problema de agentes conversando en lenguaje natural cuando podrían pasarse datos estructurados.

**¿Nos serviría?** Es el que menos nos aporta. Nuestro sistema de subagentes + skills + handoffs ya hace orquestación, pero más eficiente porque no gastamos tokens en que los agentes "conversen".
