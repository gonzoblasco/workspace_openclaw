**Quick update on the fix direction, since the PR has evolved based on the discussion here and on review.**

The PR now exposes both `inputStyle`/`inputClassName` and `visuallyHiddenStyle`/`visuallyHiddenClassName` on Checkbox, CheckboxField, Radio, RadioField, CheckboxButton, and RadioButton. This aligns with what @dylesp asked for in the thread: full style/className access to the hidden input, plus the VisuallyHidden wrapper, rather than a fixed "all zeros" prop.

The usage requires the label to be a positioned containing block, which matches the constraint @snowystinger flagged (we can't set `position: relative` on the label without it being breaking). The consumer sets it on the label or any ancestor:

```jsx
<Checkbox
  style={{position: 'relative'}}
  visuallyHiddenStyle={{inset: 0, width: 'auto', height: 'auto'}}
  inputStyle={{position: 'absolute', inset: 0, width: '100%', height: '100%'}}>
  Accept
</Checkbox>
```

I verified in a real browser (not jsdom) that this makes the hidden input's bounding box match the component, so the screen reader focus ring aligns with the visual one. The PR includes real-browser layout tests for this.
