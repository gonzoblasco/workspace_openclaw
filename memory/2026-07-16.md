## Lecciones aprendidas

### Sobre el proceso
- **Las fases se ejecutan mejor con commits atómicos.** Cada fase de create-with-ai tuvo su propio commit, lo que hace el historial legible y el progreso medible.
- **ADRs por fase.** Cada decisión importante quedó documentada. Al final tenés 6 ADRs que cuentan la historia del producto.
- **El "momento eureka" hay que capturarlo inmediatamente.** La idea de create-with-ai surgió de una conversación y se plasmó en BRIEF en minutos. Si lo dejamos para después, se pierde.

### Sobre accessible-ui
- **Los bugs más sutiles están en los edge cases.** ArrowUp que no wrappeaba, defaultActiveId sin validación — no son bugs del flujo feliz, son del flujo que nadie prueba.
- **52 tests de edge cases encontraron 3 bugs reales.** Los tests originales (68) solo cubrían flujo feliz. Los edge cases son donde viven los bugs.
- **El build de Chromatic no aporta valor en proyecto unipersonal.** Tests + axe cubren mejor que Chromatic para una librería headless.

### Sobre create-with-ai
- **El nombre lo es todo.** "create-with-ai" dice exactamente lo que hace. "create-stack-next" dice el stack, no el valor.
- **BYOK es la decisión correcta para un MVP.** No tenemos que preocuparnos por infraestructura de IA, y el usuario mantiene el control.
- **El stack adaptativo es el diferenciador clave.** Que el sistema elija el stack según el proyecto, no al revés.
- **El modo iteración es lo que lo diferencia de un scaffold.** Poder modificar proyectos existentes es lo que lo convierte en "compañero" y no en "generador de una sola vez".

### Sobre el MVP recortado (segunda sesión)
- **Un PO externo que cuestione el scope es invaluable.** La revisión de Kanam como PO reveló que el MVP era demasiado ambicioso. Recortar a Fase 0 fue la decisión correcta.
- **No vendas humo.** El modo iteración estaba en el menú principal pero no aplicaba cambios. Ocultarlo tras `--iterate` hasta que funcione es más honesto.
- **El wizard sin API key es mejor que el keyword matching.** Preguntar es más útil que adivinar. El usuario prefiere responder 5 preguntas a recibir un análisis incorrecto.
- **El scaffold generado necesita verificación real.** El primer intento de build del proyecto generado falló (tsconfig incompleto, build script incorrecto). Hay que probar el output, no solo el CLI.
- **Los ADRs se desactualizan rápido.** Los cambios de esta sesión dejaron 3 ADRs obsoletos. Hay que actualizarlos inmediatamente cuando cambian las decisiones.

### Sobre el workflow kit
- **Las skills del workspace y del kit deberían sincronizarse.** product-reset existe en ambos lados ahora. Habría que definir un proceso de sync.
