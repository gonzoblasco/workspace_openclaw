## Aprendizaje: pr_vscode_niveles — repo no existía

**Situación:** Intenté hacer push a `pr_vscode_niveles` y falló. MEMORY.md lo marca como 🧊 FREEZER, pero asumí que el repo ya existía en GitHub.

**Diagnóstico:** 
```bash
gh repo view gonzoblasco/pr_vscode_niveles
# → "Could not resolve to a Repository"
```

**Acción:**
- El proyecto estaba local en `/Users/gonzoblasco/.openclaw/workspace/projects/pr_vscode_niveles`
- Creé el repo privado en GitHub:
  ```bash
  gh repo create gonzoblasco/pr_vscode_niveles --private --source=. --push
  ```
- Falló al agregar remote (ya existía `origin`)
- Fix:
  ```bash
  git remote set-url origin git@github.com:gonzoblasco/pr_vscode_niveles.git
  git push -u origin main
  ```

**Resultado:** Repo creado y sincronizado ✅

**Lección:** No asumir que un proyecto "FREEZER" tiene repo remoto existente. Verificar con `gh repo view` antes de intentar push. Si es proyecto congelado sin repo, crearlo explícitamente.

## Hora: 11:30 GMT-3 — Filosofía Products/Projects

**Descubrimiento:** Había dos directorios `soporteml-v2`:
- `/products/soporteml-v2/` — solo archivos de producto (BRIEF, EVALUATION, DEFINITION, ROADMAP, STATUS)
- `/projects/soporteml-v2/` — código real (src/, package.json, configs, etc.)

**Decisión:** Esta separación es intencional y se adopta como filosofía para todos los productos:

| Directorio | Propósito | Contenido | Commit |
|------------|-----------|-----------|--------|
| `products/<slug>/` | Definición del producto | BRIEF, EVALUATION, DEFINITION, ROADMAP, STATUS | Workspace git (frecuente) |
| `projects/<slug>/` | Implementación | Código, configs, src/, docs técnicos | Repo separado |

**Por qué:**
- `products/` = qué y por qué (producto, mercado, decisiones)
- `projects/` = cómo (código, arquitectura técnica)
- Workspace trackea `products/` intensivamente (memoria institucional)
- Cada proyecto tiene su propio repo para `projects/` (código pesado, branches, PRs)

**Regla:** Si tiene ciclo de Product Owner completo (evaluation, definition, roadmap), va en ambos. Si es herramienta interna o experimento, solo `projects/`.
