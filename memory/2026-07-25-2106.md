## 🧠 Entendiendo el issue #686

### El contexto

En el issue #683, un usuario preguntó cómo serializar múltiples suites de tests de integración (ej: tests contra una DB real) sin tener que poner todo en un mismo archivo. La respuesta de los maintainers fue:

> Poné `.serialized` en la **suite contenedora** y todas las suites anidadas se serializan automáticamente.

```swift
@Suite(.serialized) struct DatabaseTests {}

extension DatabaseTests {
  @Suite struct ReadingTests { ... }
}

extension DatabaseTests {
  @Suite struct WritingTests { ... }
}
```

`ReadingTests` y `WritingTests` nunca se ejecutan al mismo tiempo porque `DatabaseTests` tiene `.serialized` y se propaga recursivamente.

### Lo que falta

Ese patrón **no está documentado** en `Parallelization.md`. El issue #686 pide exactamente eso: documentar el patrón de usar `.serialized` en una suite contenedora para que todas las suites anidadas se serialicen.

- `ParallelizationTrait` tiene `isRecursive: Bool` que devuelve `true` cuando tiene una dependencia

## ⚡ Mini-intro a Swift (lo que necesitás para este issue)

### 1. `struct` vs `class`

```swift
// Value type (como un record en TS, pero inmutable por defecto)
struct User {
    let name: String
    var age: Int
}

// Reference type (como class en JS/TS)
class FoodTruck {
    let name: String
    var isOpen: Bool
}
```

En swift-testing usan **`struct`** casi siempre. Value types, más seguros.

### 2. `extension`

```swift
// Podés extender un tipo en otro archivo
struct DatabaseTests {}

extension DatabaseTests {
    @Suite struct ReadingTests {}
}

extension DatabaseTests {
    @Suite struct WritingTests {}
}
```

Es como agregar métodos/propiedades a una clase en TS pero en archivos separados. No es herencia, es **extensión del tipo**.

### 3. Macros (`@Suite`, `@Test`, `#expect`)

```swift
// @Suite marca un struct como suite de tests
@Suite(.serialized) struct MyTests {
    // @Test marca una función como test
    @Test func hello() {
        #expect(1 + 1 == 2)  // #expect es como expect() en Vitest
    }
}
```

Las macros en Swift (`@`) son como decorators/annotations. Las que empiezan con `#` son **expresiones mágicas** que el compilador expande.

### 4. `async throws`

```swift
func fetchData() async throws -> Data {
    let data = try await URLSession.shared.data(from: url)
    return data
}
```

Swift tiene `async/await` nativo desde Swift 5.5. `throws` es como lanzar excepciones. `try` es el `await` de errores.

### 5. `@Suite(.serialized)` — sintaxis de traits

```swift
// .serialized es un "trait" — un modificador
@Suite(.serialized) struct MySuite {}

// Podés combinar traits
@Suite(.serialized, .tags(.critical)) struct CriticalSuite {}
```

Los traits son valores que se pasan como argumentos a la macro. `.serialized` es un `static var` en `Trait` (como una propiedad estática).

### 6. DocC — documentación

```markdown
// En Swift, la documentación se escribe con /// (triple slash)
/// A type that serializes test execution.
///
/// Use this trait when...
public struct ParallelizationTrait { ... }
```

Y los archivos `.md` en `Testing.docc/` son artículos de DocC. Usan markdown con referencias a símbolos con ` ``Trait/serialized`` `.
